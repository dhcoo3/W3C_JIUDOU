# Lua 代码规则

## 目标

本文档用于约束本项目的 Lua 代码风格，确保地图逻辑在长期维护时具备以下特性：

- 可读
- 可维护
- 可协作
- 可被静态分析工具理解

本项目要求：

- 注释必须使用中文
- 公共接口必须遵守 EmmyLua 注释规范
- 参数、返回值、数据结构必须具备明确标注

## 基本规则

### 1. 注释语言

- 所有新增注释必须使用中文
- 不允许只写英文注释
- 专有名词可保留英文原文，但解释必须使用中文

### 2. 注释粒度

以下内容必须写注释：

- 模块职责
- 公共函数
- 重要数据结构
- 非直观的序列化规则
- 平台接口封装层

以下内容不要求写注释：

- 一眼可读的简单赋值
- 明显的表遍历
- 没有任何歧义的短小逻辑

禁止写无意义注释，例如：

- `-- 设置变量`
- `-- 调用函数`
- `-- 返回结果`

### 3. EmmyLua 规则

公共函数必须根据实际情况添加：

- `---@class`
- `---@field`
- `---@param`
- `---@return`
- `---@type`
- `---@alias`

如果函数存在参数或返回值，就必须写清楚参数和返回值类型。

### 4. 公共接口规则

模块对外暴露的方法必须满足：

- 有中文说明
- 有参数标注
- 有返回值标注
- 命名清晰

例如：

```lua
---@param player player 玩家句柄
---@param key string 存档键
---@return string value 读取到的字符串值
function M.load_string(player, key)
end
```

### 5. 数据结构规则

配置表、存档结构、装备结构、掉落结构必须声明为 `---@class`。

例如：

```lua
---@class ArchiveData
---@field version integer 存档版本
---@field level integer 角色等级
---@field exp integer 角色经验
```

### 6. 模块规则

每个模块文件开头都应说明：

- 模块用途
- 该模块属于哪一层
- 是否为公共模块

推荐格式：

```lua
--- 装备系统业务入口。
--- 负责装备生成、入包、查询等核心行为。
```

### 7. 配置文件规则

所有配置文件必须：

- 使用 `---@class` 描述结构
- 使用 `---@field` 描述字段
- 不在配置文件中混入复杂逻辑

配置文件的职责应保持为：

- 枚举
- 默认值
- 权重
- 常量
- 小型只读映射

### 8. 平台接口规则

所有 KKAPI / JAPI 封装必须统一放在 `platform/` 下。

要求：

- 不能在业务层直接到处调用原生平台函数
- 平台适配层必须写清楚“真实平台行为”和“本地兜底行为”
- 平台接口返回异常时，必须有清晰注释说明

### 9. 序列化规则

涉及字符串拼接、存档编码、装备编码时，必须写明：

- 输入结构
- 输出格式
- 分隔符含义
- 空值处理方式

### 10. 调试代码规则

调试代码允许保留在 `debug/` 目录，但也必须写中文注释。

要求：

- 调试入口清晰
- 不允许把调试逻辑混入正式业务模块
- 能被统一关闭或替换

## 推荐写法

### 模块注释

```lua
--- 玩家资料平台封装层。
--- 负责读取平台昵称、平台 ID 和地图等级等只读信息。
```

### 类注释

```lua
---@class EquipmentItem
---@field uid integer 装备唯一 ID
---@field slot string 装备部位
---@field base_id string 装备基础模板 ID
---@field quality string 装备品质
---@field affixes EquipmentAffix[] 装备词条列表
```

### 函数注释

```lua
--- 读取玩家完整存档。
---@param player player 玩家句柄
---@return ArchiveData archive 玩家存档数据
function M.load_player(player)
end
```

### 返回值较多时

```lua
--- 解析词条字符串。
---@param raw string 词条序列化字符串
---@return EquipmentAffix[] affixes 词条列表
function decode_affixes(raw)
end
```

## 不推荐写法

- 只有函数名，没有任何注释
- 参数很多但不写 `---@param`
- 返回复杂表结构却不写 `---@return`
- 用中文描述不写类型
- 用类型标注却没有中文说明

## 当前执行要求

从本规则落地开始，项目中的 Lua 代码应执行以下要求：

- 新增代码必须符合本规则
- 修改旧代码时，顺手补齐相关注释
- 当前工程骨架代码需要统一补上中文注释和 EmmyLua 标注

## 当前结论

本项目 Lua 代码规范的最低要求是：

- 中文注释
- 公共接口有 EmmyLua 标注
- 数据结构有类型声明
- 平台、存档、装备、战斗等核心模块具备清晰注释
