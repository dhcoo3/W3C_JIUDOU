# 九斗项目 UI 美术规范（AI 生成初版）

> 文档状态：初版
>
> 适用范围：九斗 Warcraft III PVE 肉鸽地图的游戏内 UI、动态弹窗、HUD、提示框和 UI 美术资源。
>
> 目标：为 AI 生成图片、UI 草图和 Codex 实现 UI 提供统一、可检查的视觉约束。

## 1. 项目基线

### 1.1 运行环境

- 项目以 Warcraft III 1.27 及以下版本为基准。
- 动态 UI 使用项目的 `platform.frame` DzFrame 适配层。
- 业务层不直接调用 KKAPI/JAPI；UI 实现应通过统一的 Frame 封装层完成。
- UI 以游戏主界面 `DzGetGameUI()` 为父节点。
- 设计基准为 16:9，优先验证 1920×1080；现有 UI 设计稿和 Mockup 基准为 1672×941。
- UI 文本、数值、技能说明和按钮文字由 Lua 动态渲染，禁止把动态文字烘焙进图片。
- 项目界面以中文为主，名称、Rawcode、路径和代码标识可以使用英文。
- PNG 源图必须使用真实 Alpha，运行时 DzFrame 贴图也导出为带 8 位 Alpha 的调色板 BLP1；透明区域应透出游戏场景，不能以纯黑、深色块、白底或假棋盘格代替。

### 1.2 当前已有 UI 模块

| 模块 | 主要用途 | 当前资源目录 | 主要结构 |
|---|---|---|---|
| 选将 | 从 3 名随机英雄中选择 1 名 | `Build/ui/selectHero/` | 面板、3 张英雄卡、4 个技能图标、属性、技能详情、倒计时、刷新和确认 |
| 肉鸽强化 | 从 3 项强化中选择 1 项 | `Build/ui/rogue/` | 横向强化卡、强化图标、等级变化、说明、倒计时、刷新和确认 |
| 底部 HUD | 游戏主界面底部静态装饰 | `Build/ui/main/` | 森林主题底部底板 |
| 怪物提示 | 灾厄/Boss 等战斗信息提示 | `Build/ui/monster/` | 标题图和提示信息 |
| 英雄信息 | 属性、Tooltip 和成长数据 | `Build/map/Lua/hero/ui/` | 原生 UI 接入和动态文字 |

### 1.3 当前视觉基线

项目当前应形成以下统一印象：

> 深色森林遗迹中的古老魔法界面；青铜和暗金构成结构边框，墨绿色石材或木质纹理作为承载面，青蓝色能量晶石作为交互焦点，少量叶片和藤蔓作为自然主题装饰。

关键词：

```text
Warcraft III in-game UI
dark enchanted forest
ancient bronze and aged gold
deep teal stone and carved wood
cyan magical crystal
readable fantasy game HUD
restrained ornament
functional hierarchy
transparent game UI assets
```

不应出现的风格：

```text
现代网页后台
玻璃拟态
纯科幻 HUD
霓虹赛博朋克
塑料质感
写实摄影界面
过度发光
随机堆叠的装饰边框
大面积纯黑不透明矩形
图片内嵌中文、数字或按钮文字
```

## 2. 核心设计原则

### 2.1 可读性优先

信息层级和操作识别优先于装饰。玩家应在一眼内识别：

1. 当前界面的目的；
2. 当前需要做的主要选择；
3. 哪个选项已被选中；
4. 主要确认按钮是否可用；
5. 倒计时和剩余刷新次数。

### 2.2 一个主视觉焦点

每个界面只允许有一个主视觉焦点：

- 选将界面：当前选中的英雄卡；
- 肉鸽界面：当前选中的强化卡；
- 战斗提示：Boss/灾厄标题或关键提示；
- HUD：当前英雄、资源或主要操作区域。

其他卡片和装饰应降低亮度、饱和度或对比度，不能与主焦点竞争。

### 2.3 装饰必须服务于结构

边框、晶石、叶片、藤蔓和纹理只能用于：

- 标记面板边界；
- 分隔信息区域；
- 突出可交互元素；
- 表示选中、警告或稀有度。

装饰不能压住文字、技能图标、按钮或有效点击区域。

### 2.4 统一而非完全相同

不同模块可以有不同布局，但必须共享：

- 相同的主色和能量色；
- 相同的青铜/暗金材质语言；
- 相同的文字层级；
- 相同的选中态和禁用态逻辑；
- 相同的透明度和阴影规则。

选将卡偏向竖向英雄展示，肉鸽卡偏向横向信息展示，不能强行使用同一种卡牌比例。

## 3. 色彩规范

以下颜色是 AI 生成和设计实现的初始参考值，最终可根据游戏内截图微调。

| 用途 | 参考颜色 | 使用要求 |
|---|---|---|
| 游戏场景遮罩 | `#071012`，透明度 45%～65% | 保留地图轮廓，不使用完全不透明黑幕 |
| 面板底色 | `#101C1D`～`#182A29` | 墨绿、蓝黑、石材或木质纹理 |
| 面板深层 | `#081314` | 只用于内容底，不作为整张弹窗的唯一背景 |
| 青铜边框 | `#76542B` | 普通边框、外框和结构线 |
| 暗金边框 | `#B8893D` | 标题、主要边框和按钮边缘 |
| 高亮金色 | `#E3C26E` | 选中态、主要按钮、重要数值 |
| 魔法青蓝 | `#19B9D5` | 晶石、能量线、计时器和选中光效 |
| 主文字 | `#F3E4BE` | 标题、英雄名称、强化名称 |
| 数值文字 | `#FFFFFF` | 属性和关键结果；必须带阴影或描边 |
| 次要文字 | `#B8C2BC` | 规则说明、辅助标签和描述 |
| 禁用文字 | `#707A75` | 禁用按钮和不可用状态 |
| 警告色 | `#E58A37` | 倒计时紧迫、资源不足 |
| 错误色 | `#D44E48` | 错误、失败或不可执行提示 |

颜色使用比例建议：深色底 60%～75%，绿色/青蓝色 15%～25%，青铜/金色 8%～15%，高亮光效不超过 5%。

## 4. 布局和缩放规范

### 4.1 通用布局

- 所有弹窗默认居中，四周保留安全区域。
- 弹窗宽度通常为屏幕宽度的 70%～80%，高度通常为屏幕高度的 52%～65%。
- 不遮挡顶部游戏 HUD，除非当前任务明确要求全屏模式。
- 重要信息不放在屏幕最边缘，也不放在复杂装饰上。
- 使用明确的列、行和间距；不要依赖多个空格对齐文字。
- 卡片必须等宽、等高、等间距；任何选中态不得改变其他卡片的位置。
- 弹窗内部至少保留 24px 的内容安全边距，以 1672×941 设计稿为参考。

### 4.2 层级顺序

```text
游戏场景
  ↓
半透明遮罩
  ↓
弹窗背景和外框
  ↓
内容底板
  ↓
卡片、按钮、图标和文本
  ↓
选中态、悬停态和警告态
```

遮罩、面板、卡片、内容底板和文字应为独立层，不能把所有内容合成为一张图片。

### 4.3 当前代码布局的参考范围

现有 Lua 使用归一化 DzFrame 坐标，初版规范应兼容以下范围：

| 组件 | 现有参考尺寸或位置 | 美术约束 |
|---|---|---|
| 选将主面板 | 约 `0.690 × 0.530` | 保留内容边距，不能用素材透明边缘挤压文字 |
| 肉鸽主面板 | 约 `0.760 × 0.540` | 横向卡片区域必须在面板内部完整显示 |
| 选将英雄卡 | 约 `0.196 × 0.325` | 竖向卡牌，头像、技能和属性分区明确 |
| 肉鸽强化卡 | 约 `0.590 × 0.108` | 横向信息卡，图标、名称、等级、说明分列 |
| 选将技能图标 | 4 个等距图标 | 图标底座和点击区域大小一致 |
| 肉鸽选项 | 3 行等距卡牌 | 每行只承载一个强化选项 |

## 5. 组件规范

### 5.1 弹窗面板

- 面板必须有清晰外框、内容底和适度阴影。
- 外框采用森林藤蔓、雕刻木材、青铜和青蓝晶石的组合。
- 四角可以有装饰，但不能进入主要文字区域。
- 中心内容区使用深墨绿或蓝黑纹理，不使用纯黑填充。
- 面板内容区应保持足够安静，纹理对比度低于文字和卡片。
- 面板外框与内容底应分离，方便在 Frame 中独立缩放。

### 5.2 英雄卡

选将卡必须按以下顺序表达信息：

```text
英雄名称 / 定位
英雄头像
4 个技能图标
力量、敏捷、智力
选择状态
```

要求：

- 三张卡的外框完全一致，英雄差异由头像、名称和技能图标体现。
- 头像保持 1:1 或稳定裁切比例，不拉伸人物。
- 技能图标使用 4 个等距槽位，图标本身不带技能名称文字。
- 属性使用稳定的标签、数值和成长列，不使用不定数量空格拼接。
- 英雄名称必须有独立的安全区域，不能压在头像高亮区域上。
- 选中卡使用金色外框加青蓝能量边缘；普通卡降低亮度即可。

### 5.3 肉鸽强化卡

肉鸽卡采用横向信息布局：

```text
强化图标 | 类型标签 | 强化名称 | 当前等级 → 下一级 | 效果说明
```

要求：

- 三张卡纵向排列，卡高和间距一致。
- 图标固定在左侧，图标和图标框分离。
- 强化名称应比类型标签更突出。
- 等级变化使用清晰的 `新效果 → I`、`I → II`、`II → III` 格式。
- 描述只显示当前选择可获得的下一级效果。
- 不能把一张横向卡片误生成成竖向英雄卡。

### 5.4 按钮

- 主要按钮：确认选择、确认强化。
- 次要按钮：刷新英雄、刷新强化。
- 按钮背景和按钮文字分离，按钮文字由 Lua 渲染。
- 主要按钮比次要按钮更亮、更宽或具有更强的青蓝能量边缘。
- 未选择内容时，确认按钮必须显示禁用样式。
- 刷新次数为 0 时，刷新按钮降低亮度并禁止点击。
- 按钮必须具有普通、悬停、按下、禁用四种状态。

### 5.5 倒计时

- 倒计时是独立组件，不要把数字烘焙到图片中。
- 普通状态使用青蓝色能量环或晶石。
- 剩余 5 秒及以下使用橙色或红色提示。
- 倒计时文字必须比普通说明更醒目，但不能压过主标题和当前选项。

### 5.6 技能和强化图标

- 技能图标、肉鸽图标和头像均使用独立正方形资源。
- 图标底座、边框和内容图标分离，以便更换选中态或稀有度。
- 不在图标内生成中文、数值、冷却时间或按钮文字。
- 图标应保持清晰的主体轮廓，缩小到游戏实际尺寸后仍能识别。

## 6. 文字规范

- UI 图片不包含动态文字；名称、属性、说明、倒计时和按钮文字全部由 Lua 动态显示。
- 标题字号最大，主要操作和卡片名称次之，属性和说明再次之。
- 以 1672×941 设计稿为参考：标题约 30～36px，卡片名称约 22～28px，正文约 16～20px，辅助标签约 14～16px。
- 文字必须拥有足够对比度；复杂背景上使用深色底板、阴影或描边。
- 属性显示建议分成独立文本节点：属性名称、当前值、成长值分别对齐。
- 说明文字允许换行，但不得被边框、图标或按钮裁切。
- 不使用过多全角空格、连续空格或装饰符号进行布局。

## 7. AI 资源生成规范

### 7.1 资源拆分

AI 生成时优先生成独立 UI 源图，而不是一张完整 UI 截图。源图的边缘必须是真实透明 Alpha；运行时 BLP1 同样保留 Alpha，不能把透明区域压成深色矩形。

| 资源类型 | 当前项目示例 | 生成要求 |
|---|---|---|
| 弹窗面板 | `ui/selectHero/panel.blp` | 外框、四角与中心留空区都使用真实 Alpha；内容底如需要，另做独立深色材质面 |
| 英雄卡普通态 | `ui/selectHero/card-normal.blp` | 竖向卡框，源图不嵌入英雄头像和文字；外缘 Alpha 必须透出主面板或游戏场景 |
| 英雄卡选中态 | `ui/selectHero/card-selected.blp` | 与普通态完全同尺寸，只增加金色/青蓝选中效果 |
| 肉鸽卡普通态 | `ui/rogue/card-normal.blp` | 横向卡框，不嵌入动态文字；外缘保留真实 Alpha，内容底保持安静的深色材质 |
| 肉鸽卡选中态 | `ui/rogue/card-selected.blp` | 与普通态同坐标和同内容安全区 |
| 图标框 | `icon-frame.blp`、`skill-slot.blp` | 正方形图标框，不能遮挡图标主体 |
| 计时器 | `timer.blp` | 正方形或圆形框，数字由 Lua 显示 |
| 按钮 | `button-refresh.blp`、`button-confirm.blp` | 横向按钮背景，不能带中文 |
| 头像 | `portraits/*.blp` | 1:1 头像图，主体明确，避免白色或黑色底边 |
| 技能图标 | `skills/*.blp` | 1:1 图标，主体明确，避免图标外多余画布 |

### 7.2 源图与运行时透明度

- PNG 源图的边缘应使用真实 Alpha，便于检查抠图、边缘污染和素材安全区；提示词必须包含 `transparent background with an alpha channel`、`pure transparent PNG`。
- 负面约束必须明确：`no checkerboard pattern, no gray-and-white grid, no white background, no black background`。
- Warcraft III 1.27 的调色板 BLP1 支持 8 位 Alpha；`tools/ui_texture_export.ps1` 必须写出 Alpha 数组，禁止用任何不透明填充色替换透明像素。
- 若模型仍画出灰白棋盘格，使用 `tools/ui_alpha_cleanup.ps1` 产出新的 `*-alpha.png`，先验证 Alpha 像素数量，再转为 BLP1；禁止把假棋盘格原图直接导入地图。
- 需要静态内容底时，单独生成或绘制低对比度深墨绿材质面；不可通过把整个弹窗压成不透明矩形来模拟内容底。
- 不能出现白边、灰边、绿色溢色或发光矩形；必须分别在透明棋盘预览、深色地图和浅色地图上检查边缘。
- 选中态和普通态的画布尺寸、锚点和内容安全区域必须一致。
- 不能把多个按钮、卡片或图标拼成一张未说明的 Sprite Sheet。
- 需要平铺的纹理必须单独标记；普通边框默认不平铺、不拉伸装饰角。

### 7.3 尺寸和比例

当前仓库中已有以下源图比例和选将运行时导出尺寸，可作为实现参考：

- UI Mockup 和面板源图：1672×941，16:9；选将主框运行时 BLP：2048×1152、自适应 256 色调色板、完整 mipmap 链；
- 选将竖向卡源图：约 1024×1536；运行时 BLP：512×768；
- 技能详情条源图：约 2172×724；运行时 BLP：1024×336；
- 计时器和图标框：正方形；选将计时器运行时 BLP：512×512；
- 肉鸽横向卡：约 2172×724，后续根据实际 DzFrame 尺寸单独定义导出尺寸。

AI 生成不能只追求高分辨率，必须优先保证目标比例、真实 Alpha 边缘和可裁切安全区。生成后应使用 `tools/ui_texture_export.ps1` 转为项目需要的 BLP1 资源，并验证地图内路径、1180 字节头部、完整 mipmap 链和 8 位 Alpha 数据。选将主框由 DzFrame 加载时必须保留完整 mipmap 链；缺少低级 mip 会使该框在运行时显示为透明。

### 7.4 当前资源检查记录

本规范初版检查了现有 `Build/ui/**/source/*.png`：

- 面板和大多数边框 PNG 源图带透明通道，适合以拆分方式生成和检查。
- 选将头像源图为不透明正方形，后续实现需要明确头像裁切或遮罩方式。
- `Build/ui/rogue/source/card-selected.png` 当前是完整不透明画布；它只能作为完整选中卡底图使用，不能假定为可叠加的透明描边。
- 个别技能图标存在不一致的边缘 Alpha，生成后必须统一清理边缘。
- AI 生成新资源时应同时检查源图 Alpha 与 BLP1 Alpha 数据，而不是只检查视觉截图。

## 8. 动态状态规范

每个可交互组件至少需要定义以下状态：

| 状态 | 视觉表现 |
|---|---|
| 普通 | 正常亮度，暗金/青铜边框 |
| 悬停 | 增加少量青蓝或金色描边，不能改变布局 |
| 按下 | 边框压暗或能量收缩，反馈时间短 |
| 选中 | 明确金色外框、青蓝能量边缘或中心晶石高亮 |
| 未选中 | 降低亮度和饱和度，但文字仍可读 |
| 禁用 | 降低亮度、降低饱和度，文字使用灰绿色 |
| 警告 | 使用橙色或红色，不改变组件位置 |
| 错误 | 在对应区域显示清晰的中文错误信息 |

状态变化不能通过随机更换边框、改变卡片尺寸或移动邻近组件来表达，避免界面跳动。

## 9. 选将界面专项规范

标题：`随机英雄选择`

规则说明：`从随机的 3 位英雄中选择 1 位`

必须展示：

- 三名候选英雄；
- 英雄名称；
- 四个技能图标；
- 力量、敏捷、智力及成长信息；
- 技能详情区域；
- 20 秒倒计时；
- 刷新次数；
- 选择确认状态。

布局要求：

- 三张英雄卡横向排列并严格对齐。
- 卡片主体不能被面板边框、技能图标或底部按钮遮挡。
- 技能详情区域高度固定，内容过长时换行或截断，不得把卡片整体向下挤压。
- 选中英雄后，确认按钮变为可用；未选中时按钮明确显示“请选择英雄”。
- 刷新按钮显示剩余次数，次数为 0 时不可用。

## 10. 肉鸽强化界面专项规范

标题：`命运强化`

规则说明：`从 3 项肉鸽强化中选择 1 项`

必须展示：

- 当前英雄头像、名称和等级；
- 当前奖励序号；
- 三项强化卡；
- 强化类型；
- 强化名称；
- 当前等级和下一等级；
- 下一等级效果说明；
- 倒计时、刷新和确认状态。

布局要求：

- 三项强化卡纵向排列，不使用英雄选将的竖向卡比例。
- 每项卡牌的图标、名称、等级和说明必须在固定列中对齐。
- 说明区域必须允许中文换行，并保持卡牌总高度不变。
- 选中态只改变当前卡牌的边框和亮度，不改变其他卡牌的位置。
- 刷新和确认按钮位于面板底部，不能与最后一张卡重叠。

## 12. Codex 实现验收清单

提交 UI 改动前必须检查：

- 是否读取并遵循本规范及项目现有 UI 代码；

- 是否说明了仍然存在的资源缺口和假设。
