# 伤害属性说明

## 1. 文档定位

本文档是项目属性的统一定义文档，负责规定属性 ID、中文名称、数值单位、计算公式、取整方式和适用范围。

后续所有伤害、恢复、技能倍率、经验、金币和相关系统属性，都必须从本文档取定义。Excel 负责保存具体数值，Lua 负责运行时计算，生成的配置文件只作为编译产物使用。

新增属性时必须先修改本文档，再修改 `excelCfg/`、生成脚本和运行时代码。代码和配置不得自行创造同义 ID，例如同一个“金币掉落加成”不能同时出现 `gold_bonus`、`gold_drop_bonus` 和 `gold_bonus_percent` 三种名称。

## 2. 数值和取整规则

- 所有同步配置使用整数，不在 `excelCfg` 和生成的同步 Lua 配置中使用浮点数。
- 百分比属性使用整数表示：`15` 表示 `15%`，`100` 表示 `100%`。
- 技能十倍定点倍率使用 `MultiplierTenth` 命名：`6` 表示 `0.6×`，`10` 表示 `1.0×`，`18` 表示 `1.8×`。
- 所有“每 10 点属性”的派生效果均使用最终属性值向下取整：`floor(最终属性 / 10)`。
- 技能伤害和属性派生值使用向下取整；不得因为单个技能或属性效果引入浮点计算。
- 百分比增幅在基础值之后计算，结果使用向下取整：`floor(基础值 × (100 + 增幅百分比) / 100)`。
- 怪物生命、攻击等难度缩放遵守《项目说明.md》的十倍定点和取整规则，不得套用英雄技能的取整方式。

## 3. 英雄基础属性

力量、敏捷和智力完全使用本项目的自定义效果，不再使用 Warcraft 默认的三维属性副作用。力量、敏捷、智力带来的生命、生命增幅、普攻、技能伤害和攻击力，全部按照本文档的派生公式计算。

| 属性 ID | 中文名称 | 类型 | 当前用途 |
| --- | --- | --- | --- |
| `strength` | 力量 | 三维属性 | 英雄最终力量；每 1 点提供 25 点生命，每 10 点提供 1% 生命增幅。 |
| `agility` | 敏捷 | 三维属性 | 英雄最终敏捷；每 10 点提供 1% 普攻加成。 |
| `intelligence` | 智力 | 三维属性 | 英雄最终智力；每 10 点提供 1% 技能伤害。 |
| `primary` | 主属性 | 派生属性选择器 | 根据英雄配置中的 `Primary` 解析为力量、敏捷或智力；不通过比较三项数值推断。 |
| `attack` | 攻击 | 战斗属性 | 英雄最终攻击力；包含基础攻击、属性攻击力和装备/肉鸽固定攻击加成。 |
| `health` | 生命 | 战斗属性 | 英雄基础生命与固定生命加成；最终值还要经过生命增幅计算。 |
| `armor` | 护甲 | 战斗属性 | 英雄单位基础护甲与装备、肉鸽等固定护甲加成。 |
| `moveSpeed` | 移速 | 战斗属性 | 英雄额外移动速度，当前由属性聚合系统投影。 |
| `attack_speed_percent` | 攻击速度 | 百分比战斗属性 | 英雄最终总攻速倍率；由英雄配置的 `initialAttackSpeedPercent` 和同类加成共同决定，`100%` 表示标准攻速，`500%` 表示 5 倍攻速。 |
| `basic_attack_bonus_percent` | 普攻加成 | 百分比战斗属性 | 按百分比提高普通攻击最终伤害；敏捷每 10 点提供 1%。 |
| `health_amplification_percent` | 生命增幅 | 百分比战斗属性 | 按百分比提高基础生命与固定生命加成的合计值；力量每 10 点提供 1%。 |

`strength`、`agility`、`intelligence` 是实际数值属性；`primary` 是技能公式选择器。英雄的主属性来源必须使用英雄定义中的 `Primary` 字段，并读取最终属性值，包括已生效的等级成长、装备和肉鸽属性来源。

### 3.1 三维属性派生效果

```text
力量生命加成 = 最终力量 × 25
力量生命增幅 = floor(最终力量 / 10)%

普攻加成 = floor(最终敏捷 / 10)%

技能伤害加成 = floor(最终智力 / 10)%
```

三维属性的派生效果只计算一次。`Build/table/misc.ini` 以 w2l 可识别的 `strattackbonus`、`strhitpointbonus`、`strregenbonus`、`intmanabonus`、`intregenbonus`、`agidefensebonus`、`agidefensebase`、`agimovebonus`、`agiattackspeedbonus` 将原生主属性攻击、力量生命/生命回复、敏捷护甲/移速/攻速、智力法力/法力回复全部设为 `0`；打包后写入 `war3mapMisc.txt`（默认已为 `0` 的敏捷移速字段可能被打包器省略）。因此实现层不得再添加任何原生效果抵销。

当前目标版本为 Warcraft III 1.27。运行时保留三维属性数值以兼容原生英雄界面，但所有战斗派生值只来自本节自定义公式；敏捷不再提供任何护甲。

原生英雄属性详细提示由 `Build/map/Lua/hero/ui/attribute_tooltip.lua` 统一覆盖为一个合并 Tips：鼠标移动到英雄属性信息区或主属性图标时，显示力量、敏捷、智力三项自定义效果，并只在当前主属性下标记“主要属性”。提示中不得继续出现 Warcraft 默认的生命回复、攻速、法力和每 3 点护甲等旧效果。

### 3.2 属性攻击力

主属性和非主属性都提供攻击力，但主属性的攻击力系数更高：

```text
属性攻击力 = 主属性 × 2
           + (最终力量 + 最终敏捷 + 最终智力 - 主属性) × 1

最终攻击力 = 基础攻击力 + 属性攻击力 + 固定攻击加成
```

主属性只计入主属性项一次，不能同时作为非主属性再次计入。装备和肉鸽提供的三维属性会改变属性攻击力，提供的固定攻击力则直接进入“固定攻击加成”。

### 3.3 生命和普攻增幅

```text
生命增幅 = 力量派生生命增幅 + 其他生命增幅来源
固定生命加成 = 力量生命加成 + 其他固定生命加成
最终生命 = floor((基础生命 + 固定生命加成)
           × (100 + 生命增幅) / 100)

普攻加成 = 敏捷派生普攻加成 + 其他普攻加成来源
最终普攻伤害 = floor(原始普攻伤害
           × (100 + 普攻加成) / 100)
```

生命增幅只影响最大生命的计算结果，不放大动态生命恢复、治疗数值或当前生命值。多个同类百分比加成先相加，再统一进行一次百分比计算。

1.27 没有可靠的事件伤害改写接口。普通攻击加成由统一战斗伤害事件服务在受伤事件中读取已完成护甲结算的原始伤害，并直接扣除 `floor(原始伤害 × 普攻加成 / 100)` 点生命；补偿设置递归保护，并同时计入飘字、精英/Boss 伤害贡献、经验和金币统计。

### 3.4 新增统一属性的完整定义

| 属性 ID | 中文名称 | 单位 | 来源 | 公式 | 取整规则 |
| --- | --- | --- | --- | --- | --- |
| `attack_speed_percent` | 攻击速度 | 百分比整数 | 英雄配置 `initialAttackSpeedPercent` 与其他攻速来源 | `max(1, 初始攻速 + 其他攻速来源)` | 总攻速倍率：`100%` 表示标准，`500%` 表示 5 倍。基础攻击间隔为 `cool1` 时，预期攻击间隔为 `cool1 × 100 / 最终攻速`。敏捷原生攻速已由平衡常数归零，运行时只投影相对 `100%` 的差额。 |
| `basic_attack_bonus_percent` | 普攻加成 | 百分比整数 | 最终敏捷，以及装备、肉鸽和其他系统提供的同类百分比来源 | `floor(最终敏捷 / 10) + 其他普攻加成来源` | 派生值按 `floor(最终敏捷 / 10)`；最终普通攻击按百分比公式 `floor(...)` |
| `health_amplification_percent` | 生命增幅 | 百分比整数 | 最终力量，以及装备、肉鸽和其他系统提供的同类百分比来源 | `floor(最终力量 / 10) + 其他生命增幅来源` | 派生值按 `floor(最终力量 / 10)`；最终生命按百分比公式 `floor(...)` |

两项属性均使用属性聚合完成后的最终三维属性值；百分比来源必须先相加，再进行一次最终值计算。不得为同一来源同时写入派生属性和等效的隐藏百分比，避免重复计算。

`initialAttackSpeedPercent`、`dmgpt1`（攻击前摇）和 `backsw1`（攻击后摇）由 `unit.xlsx` 的英雄行配置；修改后必须运行配置生成与地图构建，并重新开局，已出生英雄不会热更新。最大生命在 Warcraft III 1.27 中由七位临时 `AIlf` 状态投影写入，最多额外投影 `9,999,999` 点；测试地图可输入 `-asdebug` 输出攻速诊断，输入 `-hpdebug` 输出生命公式、已投影值和实际最大生命。

## 4. 技能伤害属性和公式字段

### 4.1 伤害属性来源

| 属性字段 | 中文名称 | 可用值 | 说明 |
| --- | --- | --- | --- |
| `damageAttribute` | 伤害属性 | `primary`（英雄技能默认值）；内部允许 `strength`、`agility`、`intelligence` | 英雄技能伤害必须读取施法者的主属性；三维属性值只作为属性计算层的选择项，不能让单个英雄技能绕过 `Primary` 配置。装备自动技能同样默认使用拥有者的 `primary`。 |
| `procDamageAttribute` | 触发伤害属性 | 同上 | 普攻触发、反击、被动触发等额外伤害必须继承对应英雄或技能拥有者的 `primary`；非英雄特殊效果才可明确指定单一三维属性。 |
| `summonDamageAttribute` | 召唤物伤害属性 | 同上 | 召唤物造成伤害时使用召唤者或技能拥有者的 `primary`，不读取召唤物自身属性；只有特殊非英雄召唤物才可明确指定单一三维属性。 |

### 4.2 伤害倍率和通用增幅

| 属性字段 | 中文名称 | 单位 | 说明 |
| --- | --- | --- | --- |
| `damageMultiplierTenth` | 技能伤害十倍倍率 | 十倍定点 | 普通技能按技能等级配置的属性倍率。 |
| `procDamageMultiplierTenth` | 触发伤害十倍倍率 | 十倍定点 | 触发、反击和被动额外伤害的属性倍率。 |
| `summonDamageMultiplierTenth` | 召唤物伤害十倍倍率 | 十倍定点 | 召唤物每次伤害使用的属性倍率。 |
| `skill_damage_percent` | 技能伤害加成 | 百分比 | 肉鸽等通用来源提供的 Lua 技能最终伤害百分比增幅。 |
| `autoDamageBonus` | 自动技能伤害加成 | 百分比 | 装备被动和套装对装备自动技能造成的最终伤害增幅。 |
| `skillPowerMultiplierPercent` | 装备技能强度倍率 | 百分比 | 装备等级对装备自动技能参数的倍率，不等同于英雄的 `skill_damage_percent`。 |

当前英雄技能的基础公式为：

```text
基础伤害 = floor(伤害属性最终值 × damageMultiplierTenth / 10)
技能伤害加成 = floor(最终智力 / 10)% + skill_damage_percent + 其他技能伤害加成
最终伤害 = floor(基础伤害 × (100 + 技能伤害加成) / 100)
```

当技能的伤害属性为 `primary` 时，`伤害属性最终值`就是施法者按 `Primary` 字段解析出的最终主属性值。技能的主属性伤害倍率与智力派生的技能伤害百分比是两条独立规则：前者决定基础属性伤害，后者与现有 `skill_damage_percent` 相加后统一作用于最终伤害。

触发伤害和召唤物伤害分别使用 `procDamage*` 和 `summonDamage*` 字段。装备自动技能在上述属性计算后，继续应用装备等级技能强度倍率和 `autoDamageBonus`。

如果未来技能需要“固定基础伤害 + 属性伤害”，必须先在本文档新增明确的基础伤害字段和公式，不能在单个技能处理器中自行拼接固定值。

## 5. 恢复属性和公式

| 属性字段 | 中文名称 | 单位 | 当前用途和要求 |
| --- | --- | --- | --- |
| `healAttribute` | 恢复属性 | 属性 ID | 后续新增或重做的固定数值恢复必须指定恢复属性，默认使用施法者 `primary`。生命增幅不参与动态恢复计算。 |
| `healMultiplierTenth` | 恢复十倍倍率 | 十倍定点 | 后续固定数值恢复按恢复属性计算。 |
| `heal_percent` | 最大生命恢复比例 | 百分比 | 当前装备被动使用的恢复形式，按目标最大生命值的百分比恢复；迁移为主属性规则时必须补充属性系数。 |
| `life_regen` | 生命恢复 | 每秒或周期数值 | 当前主要用于 Boss 词缀；属于怪物专用属性，不默认套用英雄主属性。 |

固定数值恢复的标准公式为：

```text
基础恢复 = floor(恢复属性最终值 × healMultiplierTenth / 10)
最终恢复 = floor(基础恢复 × (100 + 恢复增幅百分比) / 100)
```

所有英雄技能、英雄被动、召唤物效果和装备自动技能的恢复效果，最终都必须经过统一恢复结算入口，并遵守《项目说明.md》中的主属性挂钩规则。

## 6. 经验属性

| 属性 ID | 中文名称 | 单位 | 说明 |
| --- | --- | --- | --- |
| `experience` | 经验 | 点数 | 英雄累计经验；系统同时维护当前等级、当前等级进度和下一级所需经验。 |
| `experience_bonus_percent` | 经验加成 | 百分比 | 玩家个人经验奖励增幅；在基础经验经过难度倍率后应用。运行时状态字段为 `bonusPercent`。 |
| `experienceMultiplierPercent` | 难度经验倍率 | 百分比 | PVE 难度对怪物基础经验池的全局倍率。 |
| `requiredExp` | 升级所需经验 | 点数 | 对应等级进入下一级所需的经验，不属于伤害属性，但属于经验系统的数值配置。 |
| `maxLevel` | 最大等级 | 等级数 | 当前经验系统的等级上限。 |

经验奖励的当前计算顺序为：

```text
难度经验池 = floor(怪物基础经验 × experienceMultiplierPercent / 100)
个人经验 = floor(难度经验池 × (100 + experience_bonus_percent) / 100)
```

精英和 Boss 的经验池仍按照有效伤害贡献分配，经验加成只作用于最终分配给玩家的经验，不改变伤害贡献值。

## 7. 金币属性

| 属性 ID | 中文名称 | 单位 | 说明 |
| --- | --- | --- | --- |
| `gold` | 金币 | 点数 | 玩家 Warcraft 原生金币余额。 |
| `gold_drop_bonus_percent` | 金币掉落加成 | 百分比 | 玩家个人金币掉落增幅；运行时由金币系统按玩家保存。 |
| `goldMultiplierPercent` | 难度金币倍率 | 百分比 | PVE 难度对怪物金币奖励池的全局倍率。 |
| `baseGold` | 基础金币奖励 | 点数 | 怪物按类型和等级提供的基础金币奖励。 |
| `initialGold` | 初始金币 | 点数 | 本局开始时玩家获得的金币。 |
| `maxGold` | 金币上限 | 点数 | 原生金币余额允许达到的最大值。 |
| `maxGoldDropBonusPercent` | 金币掉落加成上限 | 百分比 | 玩家金币掉落加成的上限。 |

金币奖励的当前计算顺序为：

```text
难度金币池 = floor(基础金币奖励 × goldMultiplierPercent / 100)
个人金币 = floor(难度金币池 × (100 + gold_drop_bonus_percent) / 100)
```

金币加成只影响金币奖励，不影响商店价格、初始金币、金币上限或经验奖励。

| `attackMultiplier` | 怪物攻击倍率 | PVE 难度对怪物攻击基础值的十倍定点倍率。 |
| `armorBonus` | 怪物护甲加成 | PVE 难度提供的怪物额外护甲。 |
| `goldMultiplierPercent` | 怪物金币倍率 | PVE 难度对金币奖励池的倍率。 |
| `experienceMultiplierPercent` | 怪物经验倍率 | PVE 难度对经验奖励池的倍率。 |
| `move_speed` | Boss 移速词缀 | Boss 或怪物的移动速度修正。 |
| `damage_percent` | Boss 攻击伤害词缀 | Boss 或怪物的攻击伤害百分比修正。 |
| `attack_speed_percent` | Boss 攻速词缀 | Boss 或怪物的攻击速度百分比修正。 |
| `health_percent` | Boss 最大生命词缀 | Boss 或怪物的最大生命百分比修正。 |
| `armor` | Boss 护甲词缀 | Boss 或怪物的额外护甲修正。 |
| `life_regen` | Boss 生命恢复词缀 | Boss 或怪物的周期生命恢复。 |

Boss 的 `bash`、`frost` 和 `feedback` 属于控制或特殊效果，不属于通用英雄伤害属性；如果未来要让英雄使用，必须先在本文档定义对应的英雄属性和公式。

## 10. 当前不属于统一属性的字段

- `mana0`、`manaN` 目前是单位基础配置字段，不属于英雄统一属性聚合器。
- `critChance`、`critPerStack` 目前是技能专用参数，不是全局暴击属性。
- 攻速、吸血、减伤、法术抗性等如果要成为可被装备、肉鸽和技能共同修改的属性，必须先在本文档新增统一属性 ID 和结算规则；不得重新依赖 Warcraft 三维属性的默认副作用。
- UI 中显示的经验进度、金币余额和伤害飘字是系统状态或表现数据，不应被当成新的属性 ID。

## 11. 属性计算示例

假设某英雄最终拥有：力量 `100`、敏捷 `80`、智力 `60`，主属性为力量；基础生命 `1000`，固定生命加成 `200`，基础攻击力 `200`，固定攻击加成 `0`，某技能基础属性伤害 `1000`，已有通用技能伤害加成 `20%`。

```text
力量生命加成 = 100 × 25 = 2500
力量生命增幅 = floor(100 / 10) = 10%

敏捷普攻加成 = floor(80 / 10) = 8%
敏捷护甲加成 = 0

智力技能伤害加成 = floor(60 / 10) = 6%

属性攻击力 = 100 × 2 + (100 + 80 + 60 - 100) × 1 = 340
最终攻击力 = 200 + 340 + 0 = 540

最终生命 = floor((1000 + 200 + 2500) × 110 / 100) = 4070
最终普攻伤害 = floor(500 × 108 / 100) = 540
最终技能伤害 = floor(1000 × 126 / 100) = 1260
```

示例中的 `500` 为某次普通攻击的原始伤害；技能的 `126%` 由智力派生的 `6%` 和已有通用技能伤害加成 `20%` 相加得到。

## 12. 实现和验收要求

- 伤害属性必须使用本文档规定的 ID，禁止在业务代码中写同义名称或隐藏常量。
- 技能、装备自动技能、肉鸽效果和 Boss 词缀必须区分属性来源，不能把难度倍率、个人加成和技能倍率混成一个字段。
- 力量、敏捷、智力的最终值必须先完成属性聚合，再计算生命、生命增幅、普攻加成、技能伤害和攻击力派生值；敏捷不参与护甲派生。
- 主属性攻击力按 `2` 倍计算，两个非主属性各按 `1` 倍计算；主属性不得重复计入非主属性攻击力。
- 普攻加成和生命增幅的同类百分比来源必须先相加再统一计算；生命增幅不得作用于动态生命恢复。
- 所有涉及伤害或恢复的运行时结算必须经过统一入口；不得在单个技能中直接修改目标生命而绕过属性公式。
- 1.27 普攻补偿必须只由统一战斗伤害事件服务执行；合成补偿伤害仍需进入同一统计分发链路，不能由飘字、经验或金币系统各自重复监听。
- 属性名称、公式、单位和显示格式发生变化时，必须同步修改 Excel、生成脚本、Lua 配置、运行时结算、UI 文案和测试用例。
- 多人模式下，属性来源、随机结果、倍率和取整顺序必须在所有客户端保持一致。
