# 后羿英雄设计与技能实现方案

## 1. 文档信息

- 项目：九斗
- 英雄：后羿
- 当前阶段：设计与实现方案，尚未实施
- 替换位置：现有哪吒英雄槽位 `H0N0`
- 技能槽位：沿用 `A0N1` 至 `A0N4`，对应 Q、W、E、R
- 设计约束：以 Warcraft III 1.27 及以下 API 为准，技能伤害统一由 Lua 结算，特效优先使用游戏内置资源

本文档记录后羿的技能机制、肉鸽强化、物编目标类型、Lua 处理方式和原生特效候选路径，作为后续实现和测试依据。

## 2. 英雄定位

后羿是敏捷主属性的远程物理输出英雄。普攻与技能在敌人身上积累日痕，Q 用于直线穿透，W 用于集火或弹射清怪，E 将日痕转成范围爆发，R 对指定区域进行九箭轰击。

- 普攻模型：原生弓箭手模型与弓箭远程攻击
- 主属性：敏捷
- 建议攻击射程：600
- 建议定位：中远距离持续输出、直线清线、区域爆发
- 主要短板：没有突进技能，受近身包围时较难脱身

沿用 `H0N0` 和 `A0N1` 至 `A0N4` 可以保留当前选将池与技能槽结构。单位模板应从哪吒当前的近战模板切换为原生弓箭手模板 `earc`，并把攻击范围改成远程值。初始三维属性和成长先以现有数值为测试基线，只调整主属性和敏捷成长，之后依据实测输出和生存率平衡。

## 3. 技能总览

技能数值均为首轮测试建议值，不是最终平衡值。倍率使用项目约定的十倍定点整数；例如 `8` 代表 `0.8 × 敏捷`。所有技能伤害通过统一 Lua 战斗服务结算，物编技能的直接伤害必须关闭。

| 槽位 | 技能 | 目标方式 | 基础机制 | 肉鸽方向一 | 肉鸽方向二 |
|---|---|---|---|---|---|
| Q / `A0N1` | 贯日箭 | 指向地面 | 沿施法方向发射长箭，射程 900、宽度 96，最多命中 4 名敌人；每级伤害建议为 `0.8 / 1.1 / 1.4 × 敏捷`。 | 长虹贯日：穿透上限 `+1 / +2 / +3`，修正键 `target_count_add`。 | 裂云：本技能伤害 `+10% / +20% / +30%`，修正键 `damage_percent_add`。 |
| W / `A0N2` | 连珠追日 | 指向敌人 | 锁定目标，在约 0.18 秒间隔内射出 3 支箭；每箭伤害建议为 `0.4 / 0.5 / 0.6 × 敏捷`。技能射程建议 750，冷却建议 `9 / 8 / 7` 秒。 | 七曜连珠：每次施放额外射出 `1 / 2 / 3` 支箭，修正键 `projectile_count_add`。 | 追星折返：每支箭额外弹射 `1 / 2 / 3` 个未命中的附近敌人，修正键 `bounce_count_add`。 |
| E / `A0N3` | 金乌灼痕 | 被动 | 普攻或技能命中后给目标附加一层日痕，最多 3 层，5 秒未再命中则消退。叠满后爆发，对目标周围半径 180 的敌人造成建议为 `0.6 / 0.8 / 1.0 × 敏捷` 的伤害，并减速 20%、持续 1 秒。 | 烈阳焚身：日痕爆发伤害 `+20% / +40% / +60%`，修正键 `proc_damage_percent_add`。 | 余烬燎原：日痕爆发范围 `+60 / +120 / +180`，修正键 `area_add`。 |
| R / `A0N4` | 射日·九曜坠落 | 指向地面 | 指定半径 360 的区域，约 2 秒内落下 9 支日箭；普通箭每支伤害建议为 `0.3 × 敏捷`，第九箭落在中心并造成 `1.0 × 敏捷` 伤害。每次爆炸范围建议 110，第九箭范围建议 180。冷却建议 `70 / 60 / 50` 秒，耗魔建议 `120 / 160 / 200`。 | 天弓再张：额外追加 `1 / 2 / 3` 支普通日箭，第九箭仍作为最后一击，修正键 `projectile_count_add`。 | 坠日余威：第九箭伤害 `+20% / +40% / +60%`，修正键 `final_damage_percent_add`。 |

每个强化效果最高三级，按项目现有肉鸽规则累计生效。两条强化方向是独立效果卡，不设强制互斥；玩家可以同时升级同一个技能的两条分支。

## 4. 技能机制实现

### 4.1 Lua 模块边界

建议新增 `Build/map/Lua/rogue/skills/houyi.lua`，由 `rogue/main.lua` 在英雄选择完成后启动。后羿专属施法与状态逻辑放在该模块，不继续扩展通用的 `hero_damage.lua`。

模块通过 `EVENT_PLAYER_UNIT_SPELL_EFFECT` 识别 `A0N1`、`A0N2` 和 `A0N4`，通过统一伤害服务确认后羿普攻的实际伤害事件。技能伤害调用 `combat.damage.deal`，数值使用 `combat.skill_damage.calculate`，主属性读取英雄配置中的 `AGI`，不得直接调用绕过项目伤害统计的伤害接口。

模块状态按英雄隔离。每个英雄状态至少包含：日痕目标表、施法序号、当前延时箭雨施放状态和临时特效/弹道对象。目标表以单位句柄或句柄 ID 为键，目标死亡、层数过期或英雄结束时清理。

### 4.2 Q：贯日箭

1. 技能物编使用指向地面的目标方式，Lua 读取施法者坐标与目标点。
2. 将目标方向归一化；目标距离超过 900 时截断到最大射程。
3. 枚举施法方向附近的敌人，计算敌人到线段的垂直距离，只保留落在 96 宽度判定带内的敌人。
4. 按敌人在线段上的投影距离排序，从近到远结算；基础上限为 4，再叠加 `target_count_add`。
5. 每个目标每次 Q 只结算一次伤害和一次日痕，避免群体碰撞或持续视觉采样造成重复命中。

现有 `hero_damage.lua` 已包含线段距离计算辅助逻辑，但当前哪吒 W 会对整条线上的敌人直接结算，未按距离顺序限制穿透目标数。实现时应提取或重写为带距离排序和最大目标数的通用检测函数。

### 4.3 W：连珠追日

1. 技能物编使用敌方单位目标方式，Lua 读取目标单位并在施法时记录目标句柄。
2. 创建一个施法专属计时器，按 0.18 秒间隔发射 3 支基础箭；肉鸽额外箭数增加发射次数。
3. 每支箭单独结算一次命中。若拥有弹射强化，则从当前命中点开始搜索 350 范围内尚未被该支箭命中的最近敌人，并继续弹射至强化上限。
4. 每支箭维护自己的已命中目标集合，防止同一支箭重复命中同一个单位；目标死亡或离开有效搜索范围时，按最近的合法敌人继续寻找。
5. 计时器结束后销毁，释放群组、弹道单位和特效句柄。

额外箭数与弹射数可以组合，因此必须在测试地图中检查三级组合的总命中量。可在后续平衡时限制每次施放的总命中数，但首版先保留分支叠加，让两种构筑方向都能生效。

### 4.4 E：金乌灼痕

日痕状态以目标为单位单独记录，建议数据字段为 `{stacks, expiresAt, effect}`。普攻只在统一伤害服务确认真实普攻伤害后叠层；技能由对应技能处理器在 Lua 命中结算时叠层，避免物编和 Lua 各记一次。

同一技能施放对同一目标最多叠一层日痕，W 的多支箭和 R 的多段落箭不会在一次施放中让单个目标瞬间叠满。普攻每次实际命中分别叠一层。叠满三层时，日痕立即爆发并清零；新一层刷新 5 秒过期时间。

爆发范围内的所有敌人受到主属性伤害和减速。减速使用单独的短时 Buff 物编效果，避免直接覆盖单位移速属性。若目标死亡，立即释放该目标持有的日痕特效和状态。

### 4.5 R：射日·九曜坠落

1. 技能物编使用指向地面的目标方式，Lua 读取目标中心点并限制施法距离。
2. 启动一个施法专属计时器，按固定间隔依次生成 8 个外围落点；最后一箭固定落在中心点。
3. 外围落点按施法序号旋转固定角度生成，不使用客户端本地随机。第九箭单独应用 `final_damage_percent_add`。
4. 每支箭在落点进行一次范围判定和伤害结算；同一目标同一次施放最多获得一层日痕。
5. 肉鸽额外箭数追加普通箭，落点继续使用同一确定性几何规则，第九箭保持为最后一击。

每次施法的中心坐标、施法序号和箭序号都保存在独立状态中；不能把这些数据放进模块级共享临时变量，否则多人同时施放时会串线。

## 5. 多人同步与性能要求

- 技能命中、伤害、日痕层数、Buff、计时器和弹道单位都属于同步游戏状态，所有客户端执行相同逻辑，不放进 `GetLocalPlayer` 分支。
- Q、W、R 不使用客户端本地随机；目标排序按确定性规则执行，R 使用固定几何落点。
- 所有 Lua 技能伤害通过统一伤害服务，确保飘字、精英/Boss 伤害贡献、经验和金币统计能读取这些伤害。
- 每轮枚举后销毁单位组；临时特效和日痕特效有明确销毁条件；计时器完成或施法者状态失效后停止并释放。
- 限制每次 R 施放只保留一个箭雨计时器；多人测试时关注同时施放产生的计时器数量和单位枚举开销。
- 按项目 1.27 兼容约束，不依赖高版本 `BlzSetSpecialEffectPosition` 一类移动特效接口。需要移动弹道时使用 Lua 计时器驱动的视觉弹道单位，或调用原生技能弹道壳；碰撞与伤害仍由 Lua 判定。

## 6. 原生魔兽特效方案

首版不导入自制模型。技能视觉分成“箭矢弹道、命中爆发、日痕状态、区域预警”四层；实际伤害和碰撞由 Lua 决定，原生模型只负责演出。

| 用途 | 原生模型路径 | 建议用途 |
|---|---|---|
| 普攻/普通连射箭 | `Abilities\Weapons\Arrow\ArrowMissile.mdl` | W 的基础箭矢，清晰易读，不为每支箭叠加大爆炸。 |
| 贯日/日箭弹道 | `Abilities\Weapons\SearingArrow\SearingArrowMissile.mdl` | Q 和 R 的火焰箭弹道；若目标客户端显示不合适，回退普通箭矢。 |
| 强化日箭备选 | `Abilities\Weapons\PhoenixMissile\Phoenix_Missile_mini.mdl` | 用于 Q 的强化弹道或 R 的第九箭。先检查它是否显得像箭，而不是单纯火球。 |
| 日痕目标附着 | `Abilities\Spells\NightElf\Immolation\ImmolationDamage.mdl` | 目标有日痕时附着在目标身上；同一目标最多保留一个提示特效，叠层数由图标/数字或爆发提示表达。 |
| 日痕爆发/落箭命中 | `Abilities\Spells\Human\FlameStrike\FlameStrike1.mdl` | E 爆发、R 普通箭落点的短促火焰冲击。 |
| 落点预警/中心印记 | `Abilities\Spells\Human\FlameStrike\FlameStrikeTarget.mdl` | R 施放中心和第九箭落点提示；预警只做短暂视觉，不承担伤害。 |
| 地面余烬 | `Abilities\Spells\Human\FlameStrike\FlameStrikeEmbers.mdl` | E 或第九箭命中后留下短暂余烬，限制持续时间和同时存在数量。 |
| 大招起手光效 | `Abilities\Spells\NightElf\Starfall\StarfallCaster.mdl` | R 开始时在施法中心播放一次星落式起手效果。 |
| 火雨落点备选 | `Abilities\Spells\Demon\RainOfFire\RainOfFireTarget.mdl` | R 的普通落箭点候选；如果当前 1.27 客户端路径不可用，改用 FlameStrike 命中效果。 |

模型路径参考 Warcraft III 原生资源列表及技能脚本示例：普通/燃烧箭路径可参考 [HIVE 导弹系统示例](https://www.hiveworkshop.com/threads/missile-system-by-adik.302575/)，凤凰导弹名称可参考 [Phoenix Missile 模型讨论](https://www.hiveworkshop.com/threads/model-request.134158/)，FlameStrike 与 Starfall 路径可参考 [HIVE 默认技能效果示例](https://www.hiveworkshop.com/threads/default-spells-triggered-1-08.254699/) 和 [隐藏模型列表](https://www.hiveworkshop.com/threads/hidden-models-in-warcraft-3.16793/)，Immolation 附着效果可参考 [Immolation Art 说明](https://www.thehelper.net/threads/immolation-art.62599/)。这些链接用于定位资源名；打包前仍须在项目目标客户端逐个运行确认。

### 6.1 弹道实现选择

`AddSpecialEffect` 只能在指定坐标生成特效，不能作为 1.27 通用移动弹道接口。首版实现按以下顺序选择：

1. 若技能壳可提供正确的原生弹道且能将原生伤害设为 0，优先用其呈现飞行；Lua 独立处理命中。
2. 若技能壳不能满足 Q/W/R 的目标方式，新增一个不可选中、无攻击、无碰撞的视觉弹道单位，使用原生箭矢模型并由 1.27 可用的单位坐标接口移动。
3. 若目标客户端不能把箭矢模型作为单位模型稳定显示，退回到命中点特效与施法方向提示，不引入外部模型。

所有备选均保留 Lua 碰撞/伤害判定为唯一权威。不得因原生弹道的飞行碰撞再次触发伤害。

## 8. 物编技能壳要求

- Q、R 必须是地面目标技能，允许 Lua 读取目标坐标。
- W 必须是敌方单位目标技能；连续箭数由 Lua 与肉鸽层数决定。
- E 是被动技能，学习后启用日痕监听，不需要施法目标。
- 四个技能的物编伤害、周期伤害和额外打击均设为 0，避免与 Lua 重复结算。
- 物编仍负责技能栏位置、热键、施法动作、必要的范围指示和目标约束。
- 使用原生技能模板前要核对其实际订单字符串和允许目标；不能只换名字后保留不匹配的技能父级。
- Q、W、R 的射程、区域半径、冷却和耗魔都需要与 Lua 运行时配置保持一致。

## 9. 验收测试

### 单人机制

- Q 只命中射线判定带内敌人，命中顺序从近到远，达到穿透上限后停止。
- Q 的 `target_count_add` 与 `damage_percent_add` 分别生效，三级后不越界。
- W 基础三箭按时间间隔命中锁定目标；额外箭和弹射强化能正确叠加，单支箭不会重复命中同一目标。
- E 日痕按目标分别累计，五秒未命中会消退；三层触发一次爆发并重置，目标死亡后不遗留特效/状态。
- 技能多段伤害不会使 E 因同一次施法瞬间叠满；普攻只在实际造成伤害后叠层。
- R 顺序落下 9 箭，第九箭始终打中心且伤害强化正确；额外箭分支不改变第九箭身份。
- 连续施放 R/W 时计时器互不串线，目标离开、死亡或施法者死亡时行为符合预定规则。

### 肉鸽与配置

- 后羿八条肉鸽效果全部进入英雄专属奖励池，每条效果可升至三级且不能超过三级。
- 选择肉鸽后对应 modifier 只作用于后羿和指定技能，不影响其他英雄。
- 生成器校验 H0N0 技能 Rawcode、效果数量、整数数组、图标路径和运行时参数。
- 选将面板、英雄状态提示和技能说明与实际目标方式、冷却及伤害公式一致。

### 多人同步与构建

- 两名后羿同时释放 W/R 时，弹道顺序、落点、命中目标、日痕层数、伤害和减速完全一致。
- 房主与非房主各自施放时，所有同步游戏状态结果一致；UI 本地显示不修改共享状态。
