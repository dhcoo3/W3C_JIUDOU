# 九斗肉鸽系统设计文档

## 1. 文档信息

- 项目：九斗
- 系统：英雄肉鸽成长与升级奖励系统
- 当前版本：V1.1 首版实现
- 适用模式：PVE 肉鸽模式
- 核心规则：每名玩家的英雄从首次奖励等级起，按配置的奖励等级间隔独立出现一次“3 选 1”肉鸽奖励界面

本文档用于统一肉鸽系统的玩法规则、配置格式、Lua 运行时结构、多人同步方式、UI 流程和物编流程。

## 2. 设计目标

### 2.1 玩家独立

每名玩家只为自己的英雄生成肉鸽奖励。玩家 A 升级时，玩家 B 不会看到玩家 A 的选项，也不会被玩家 A 的选择阻塞。

### 2.2 房主权威

肉鸽选项的随机结果、玩家选择是否合法、效果是否成功发放，均由房主或同步权威端决定。客户端 UI 只负责展示和发送选择请求。

### 2.3 配置驱动

英雄技能、肉鸽效果、等级数值、权重和互斥关系全部由配置表驱动，技能逻辑只读取最终修正值，不直接依赖某一个肉鸽 ID。

### 2.4 基础技能与肉鸽效果分离

物编只负责基础技能和视觉表现；Lua 负责肉鸽效果、英雄状态、属性刷新、技能运行时修正和奖励同步。

## 3. 核心玩法流程

```text
英雄获得经验
    ↓
英雄等级提升
    ↓
记录待处理的肉鸽奖励次数
    ↓
房主为该玩家生成 3 个合法选项
    ↓
通过同步消息发送选项 ID
    ↓
该玩家本地显示 3 选 1 界面
    ↓
玩家点击其中一个选项
    ↓
房主验证选择并发放效果
    ↓
同步最终结果
    ↓
刷新英雄属性和技能运行时数据
```

默认规则为英雄达到 2 级时第一次触发奖励，之后每 3 级触发一次，即 2、5、8、11……级。`settings` 表中的 `firstRewardLevel` 控制首次触发等级，`rewardLevelInterval` 控制后续间隔；将间隔改为 1 即可恢复每级奖励。若需要英雄出生时就选择一次肉鸽，只需将首次触发等级改为 1。

## 4. 升级奖励规则

### 4.1 每名玩家独立维护奖励状态

每名玩家至少维护以下数据：

```lua
---@class RoguePlayerState
---@field playerId integer 玩家编号
---@field hero unit 玩家英雄
---@field heroRawcode string 英雄 Rawcode
---@field rogueLevel integer 已处理的肉鸽等级
---@field pendingRewards integer 尚未处理的奖励次数
---@field offerSerial integer 当前奖励序号
---@field currentOffer RogueOffer|nil 当前展示的奖励
---@field owned table<string, integer> 已拥有的肉鸽效果及等级
---@field common table<string, number> 已汇总的通用属性
---@field skills table<string, table<string, number>> 已汇总的技能属性
```

### 4.2 多次升级的处理

如果一次经验变化导致英雄连续提升多个等级，不应同时弹出多个窗口。应该使用队列：

```text
pendingRewards = pendingRewards + 本次提升的等级数
    ↓
当前奖励选择完成
    ↓
pendingRewards > 0 时继续生成下一次奖励
```

### 4.3 玩家未选择时的处理

奖励界面需要有倒计时。倒计时结束后由房主执行默认选择，建议规则如下：

1. 优先选择玩家当前已拥有且可以继续升级的效果；
2. 没有可升级效果时，选择第一个合法选项；
3. 默认选择也必须经过房主的发放流程。

## 5. 肉鸽效果分类

### 5.1 英雄专属技能肉鸽

每个英雄有 4 个技能，每个技能设计 2 个肉鸽方向，共 8 个专属效果。

以孙悟空为例：

| 技能 | 效果一 | 效果二 |
|---|---|---|
| A0W1 如意横扫 | 影响范围增加 | 额外攻击目标数增加 |
| A0W2 筋斗突进 | 突进距离增加 | 落点范围增加 |
| A0W3 齐天战意 | Buff 持续时间增加 | 每层攻速或暴击收益增加 |
| A0W4 毫毛化身 | 召唤数量增加 | 召唤持续时间或触发概率增加 |

每个技能肉鸽效果都拥有 3 个等级。效果等级可以重复获得，但不能超过 3 级。

### 5.2 通用肉鸽

通用肉鸽不绑定具体英雄或技能，可以出现在所有玩家的奖励池中。

建议第一批通用肉鸽包括：

- 攻击力增加
- 防御力或护甲增加
- 最大生命值增加
- 最大法力值增加
- 移动速度增加
- 攻击速度增加
- 技能伤害增加
- 冷却时间减少
- 技能范围增加
- 生命回复增加
- 主属性增加
- 力量、敏捷、智力成长系数增加

成长系数肉鸽应进入 Lua 的成长计算，不建议直接动态修改物编中的英雄成长字段。

建议新增数据源文件：

```text
Build/table/roguelike.ini
```

示例：

```ini

Icon = "ui\\rogue\\wukong_q_area.blp"
ModifierKey = "area_add"
Operation = "add"
Values = {60, 110, 180}
MaxLevel = 3
Weight = 100

[R_H0W0_A0W1_02]
Type = "Skill"
Hero = "H0W0"
Skill = "A0W1"
Name = "横扫·连击"
Description = "如意横扫额外攻击 1 / 2 / 3 个目标。"
Icon = "ui\\rogue\\wukong_q_target.blp"

Weight = 100

[R_COMMON_ATTACK]
Type = "Common"
Name = "武力强化"
Description = "攻击力增加 8% / 16% / 28%。"
Icon = "ui\\rogue\\common_attack.blp"
ModifierKey = "attack_percent"
Operation = "add"
Values = {8, 16, 28}
MaxLevel = 3
Weight = 100
```

### 6.1 字段说明

| 字段 | 说明 |
|---|---|
| Type | `Skill` 技能肉鸽，`Common` 通用肉鸽，`Special` 特殊逻辑 |
| Hero | 绑定英雄 Rawcode；通用肉鸽为空 |
| Skill | 绑定技能 Rawcode；通用肉鸽为空 |
| ModifierKey | 运行时修正类型 |
| Operation | `add` 加法、`percent` 百分比、`max` 取最大值、`unique` 唯一效果 |
| Values | 1、2、3 级的最终数值 |
| MaxLevel | 最大等级，通常为 3 |
| Weight | 随机权重 |
| Icon | 肉鸽界面显示图标 |


## 7. 选项生成规则

### 7.1 选项池

每次生成奖励时，候选池由以下内容组成：

```text
当前英雄的技能肉鸽
+
通用肉鸽
+
满足前置条件的特殊肉鸽
```

不允许出现以下选项：

- 不属于当前英雄的技能肉鸽；
- 已达到 3 级的效果；
- 与当前已有效果互斥的效果；
- 不满足前置条件的效果；
- 当前模式禁用的效果。

### 7.2 三选一要求

每次奖励必须生成 3 个不同的效果 ID。建议优先保证三种选择方向不同：

```text
技能强化 + 通用属性 + 技能强化
```

如果合法池不足 3 个，可以使用以下兜底顺序：

1. 从已拥有且未满级的效果中补足；
2. 从通用肉鸽中补足；
3. 使用配置好的“万能属性碎片”作为最后兜底。

不能向玩家发送空选项，否则 UI 和同步协议都需要额外处理。

### 7.3 随机权重

随机由房主执行。使用“本局种子 + 玩家编号 + 肉鸽等级 + 奖励序号”作为随机上下文，保证日志可追踪。

客户端不能自行随机生成选项，只能展示房主发送的三个效果 ID。

## 8. 多人同步协议

推荐沿用当前选将系统的同步模式。

### 8.1 房主发送奖励

```text
ROGUE_OFFER|sessionId|playerId|offerSerial|rogueLevel|effectId1,effectId2,effectId3
```

示例：

```text
ROGUE_OFFER|12|1|4|5|R_H0W0_A0W1_01,R_COMMON_ATTACK,R_H0W0_A0W2_02
```

### 8.2 玩家发送选择

```text
ROGUE_PICK|sessionId|playerId|offerSerial|effectId
```

玩家只能提交自己的 `playerId`，并且只能选择当前房主发给自己的三个效果之一。

### 8.3 房主发放结果

```text
ROGUE_APPLY|sessionId|playerId|offerSerial|effectId|newLevel
```

收到发放消息后，各客户端更新本地 UI 和英雄表现。实际效果必须由房主验证后确认，不能只依赖客户端点击事件。

## 9. Lua 模块划分

建议新增以下模块：

```text
Build/map/Lua/rogue/
├─ config.lua       配置读取和数据校验
├─ state.lua        玩家肉鸽状态
├─ pool.lua         奖励池和合法性筛选
├─ offer.lua        三选一生成
├─ reward.lua       同步、选择和发放
├─ attribute.lua    通用属性计算
├─ skill.lua        技能肉鸽查询和特殊 Hook
└─ ui.lua           肉鸽奖励界面
```

### 9.1 推荐公共接口

```lua
--- 创建玩家的肉鸽运行时状态。

---@param heroRawcode string 英雄 Rawcode

end

--- 通知英雄升级并排队肉鸽奖励。
---@param state RoguePlayerState 肉鸽状态

---@return nil
function rogue.on_hero_level_up(state, levelCount)
end

--- 获取技能肉鸽修正值。

end

--- 获取通用肉鸽修正值。

function rogue.get_common_value(state, modifierKey)
end

--- 给玩家发放一个肉鸽效果。
---@param state RoguePlayerState 肉鸽状态
---@param effectId string 肉鸽效果 ID
---@return boolean applied 是否成功发放
function rogue.apply_effect(state, effectId)
end
```

## 10. 技能结算方式

技能释放时只读取基础值和肉鸽修正值：

```lua
local baseArea = 325
local areaAdd = rogue.get_skill_value(state, "A0W1", "area_add")
local finalArea = baseArea + areaAdd

local baseTargetCount = 3
local targetAdd = rogue.get_skill_value(state, "A0W1", "target_count_add")
local finalTargetCount = baseTargetCount + targetAdd
```

适合统一处理的效果包括范围、距离、目标数、伤害倍率、冷却和持续时间。

以下效果需要专属 Hook：

- 额外释放一次技能；
- 产生第二段伤害；
- 额外生成投射物；
- 击杀后爆炸；
- 技能命中后弹射；
- 召唤物拥有额外技能；
- 低血量触发特殊效果。

示例：

```lua
skill_hooks.on_hit["R_H0W0_A0W1_02"] = function(context, level)
    -- 根据肉鸽等级执行额外命中逻辑
end
```

## 11. 通用属性计算

所有属性应从基础值重新计算，不要在当前值上重复叠加。

```text
最终攻击力
= 物编基础攻击
+ 英雄属性提供的攻击
+ 装备攻击
+ 肉鸽固定攻击
× (1 + 肉鸽攻击百分比)
```

```text
最终移动速度
= 物编基础移速
+ 装备移速
+ 肉鸽移速
```

成长类效果建议按英雄等级重新计算：

```text
最终力量
= 基础力量
+ (基础力量成长 + 肉鸽力量成长) × (英雄等级 - 1)
```

属性刷新统一入口：

```lua
rogue.refresh_hero_stats(state)
```

该函数可以同时刷新攻击、护甲、生命、法力、移动速度和成长属性。

## 12. UI 设计要求

肉鸽奖励界面至少包含：

- 当前英雄头像和名称；
- 当前英雄等级；
- 本次奖励序号；
- 三张肉鸽卡牌；
- 肉鸽名称；
- 肉鸽图标；
- 当前等级和下一级数值；
- 效果说明；
- 倒计时；
- 当前已拥有的等级；
- “选择”按钮或整张卡片点击区域。

每名玩家只在自己的本地客户端显示自己的奖励窗口。其他玩家可以继续刷怪、移动和处理自己的升级奖励。

同一玩家如果存在多个待处理奖励，只显示一个窗口，前一个选择完成后再显示下一个。

## 13. 物编流程

### 13.1 英雄和基础技能

在物编或对应的 `Build/table/unit.ini`、`Build/table/ability.ini` 中配置：

- 英雄基础属性；
- 英雄成长；
- 4 个基础技能；
- 技能的 3 个基础等级；
- 基础冷却、范围、距离、消耗和图标。

### 13.2 Buff 和 Debuff

只有需要在游戏中显示状态图标的效果才制作物编 Buff。纯数值型肉鸽不需要创建 Buff。

### 13.3 肉鸽卡牌图标

肉鸽卡牌推荐直接使用独立贴图路径。若需要使用物编资源，可创建展示用物品或技能，但它们只负责名称、说明和图标，不负责实际效果。

### 13.4 配置生成

需要扩展 `generate_lua_config.ps1`，让它读取 `Build/table/roguelike.ini` 并生成：

```text
Build/map/Lua/config/roguelike.lua
```

生成后由 Lua 模块读取，禁止直接修改生成文件。

## 14. 配置校验

地图启动时应检查：

- 每个英雄是否存在 4 个技能；
- 每个技能是否存在 2 个专属肉鸽效果；
- 每个效果是否拥有 3 个等级数值；
- 数值类型是否正确；
- 技能 Rawcode 是否存在；
- 效果 ID 是否重复；
- 效果是否绑定了不存在的英雄；
- 权重是否大于等于 0；
- `MaxLevel` 是否为 1 到 3；
- 每个英雄的合法奖励池是否至少可以生成 3 项。

发现错误时应直接打印明确的配置错误，并阻止肉鸽系统启动，避免游戏过程中出现空卡牌或同步异常。

## 15. 物编与 Lua 的职责边界

| 功能 | 物编 | Lua |
|---|---:|---:|
| 英雄基础属性 | 是 | 读取并计算最终值 |
| 技能图标和基础说明 | 是 | 读取 |
| 基础冷却、范围和距离 | 是 | 读取并修正 |
| 运行中范围增加 | 否 | 是 |
| 运行中目标数增加 | 否 | 是 |
| 通用攻击、防御、移速 | 基础值 | 最终值计算 |
| 肉鸽等级和拥有记录 | 否 | 是 |
| 随机 3 选 1 | 否 | 是 |
| 多人同步 | 否 | 是 |
| Buff 图标和状态表现 | 是 | 添加、移除和刷新 |
| 特殊触发逻辑 | 否 | 是 |

## 16. 实施阶段

### 第一阶段：基础框架

- 新增 `roguelike.ini`；
- 扩展配置生成脚本；
- 创建玩家肉鸽状态；
- 实现效果等级叠加；
- 实现通用属性刷新。

### 第二阶段：升级和奖励

- 接入英雄升级事件；
- 实现每名玩家独立奖励队列；
- 实现房主生成 3 个选项；
- 实现 `OFFER`、`PICK`、`APPLY` 同步协议；
- 实现超时默认选择。

### 第三阶段：UI

- 创建三选一卡牌界面；
- 显示效果等级和升级数值；
- 接入倒计时；
- 支持多个待处理奖励顺序显示。

### 第四阶段：技能接入

- 接入 4 个英雄的 4 个技能；
- 先实现范围、距离、伤害、目标数等通用修正；
- 再实现额外投射物、额外召唤、击杀触发等特殊 Hook。

### 第五阶段：测试与平衡

- 单人连续升级测试；
- 多人同时升级测试；
- 多人不同时间升级测试；
- 超时和断线测试；
- 重复获取和满级效果测试；
- 选项不足 3 个时的兜底测试；
- 技能、装备、通用肉鸽同时存在时的属性计算测试。

## 17. 验收标准

肉鸽系统完成后，应满足以下条件：

1. 每名玩家的肉鸽奖励完全独立；
2. 英雄达到首次奖励等级后，能按配置的等级间隔产生奖励；
3. 每次奖励固定显示 3 个合法且不重复的选项；
4. 玩家只能选择自己收到的选项；
5. 房主能够验证并同步最终结果；
6. 肉鸽效果最多升到 3 级；
