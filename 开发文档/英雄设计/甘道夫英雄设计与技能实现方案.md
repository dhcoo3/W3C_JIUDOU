# 甘道夫英雄设计与技能实现方案

## 1. 文档信息

- 项目：九斗
- 英雄：甘道夫
- 当前阶段：设计与实现方案，尚未实施
- 替换位置：现有牛魔王英雄槽位 `H0B0`
- 技能槽位：沿用 `A0B1` 至 `A0B4`，对应 Q、W、E、R
- 设计约束：以 Warcraft III 1.27 及以下 API 为准；技能伤害与治疗统一由 Lua 战斗/恢复服务结算；Excel 是配置数据源；特效优先使用游戏内置资源

本文沿用《后羿英雄设计与技能实现方案》的格式，给出英雄定位、技能与肉鸽分支、运行机制、原生特效候选、配置修改范围和验收项目。本文仅供评审，当前不修改物编、Excel、Lua 或地图资源。

## 2. 英雄定位

甘道夫是智力主属性的远程法术控制与团队守护英雄。Q 提供远程点杀和弹射清怪，W 负责远程打断，E 在队伍成员濒危时施以援护，R 在指定区域持续灼烧敌人。

- 主属性：智力
- 建议攻击方式：远程法杖/法术弹道
- 建议攻击射程：550
- 建议角色定位：远程法术输出、单体控制、危急救援、区域清场
- 主要短板：失去牛魔王的嘲讽和近战承伤能力；自身生命与护甲不宜沿用牛魔王的坦克数值
- 肉鸽成长：四个技能各有两个三级专属效果；两个分支可分别升级，不强制互斥

当前仓库没有发现甘道夫专用模型文件。首版建议使用原生人族法师外观作占位；若要保留甘道夫辨识度，再单独引入经过许可且适配项目的法杖白袍模型。攻击射程、攻击弹道和模型应作为同一项资源配置核对，不能只把近战牛头人模型的射程改成远程。

替换后队伍少一个传统主坦。E 的援护只能缓冲濒危情况，不等同于持续嘲讽或承伤；如果当前刷怪强度依赖牛魔王稳定拉怪，关卡仍需由其他英雄、装备或怪物数值承担这部分压力。

## 3. 技能总览

下列倍率均使用项目的十倍定点格式，例如 `8` 表示 `0.8 × 智力`。数值为首轮测试建议值；每次技能伤害和治疗都读取英雄当前主属性，不把本文的初始属性写成固定伤害。

| 槽位 | 技能 | 目标方式 | 基础机制 | 肉鸽方向一 | 肉鸽方向二 |
|---|---|---|---|---|---|
| Q / `A0B1` | 星火术 | 敌方单位 | 对射程内目标造成 `0.8 / 1.0 / 1.2 × 智力` 魔法伤害。冷却建议 `8 / 7 / 6` 秒，耗魔 `55 / 65 / 75`。 | **星火连锁**：命中后依次弹射 `1 / 2 / 3` 个未命中敌人，后续目标承受基础伤害的 60%；修正键 `bounce_count_add`。 | **白焰聚焦**：本技能伤害 `+10% / +20% / +30%`；修正键 `damage_percent_add`。 |
| W / `A0B2` | 法杖封界 | 敌方单位 | 远程法术弹命中后造成 `0.6 / 0.8 / 1.0 × 智力` 魔法伤害，并眩晕 `0.8 / 1.0 / 1.2` 秒。射程建议 650，冷却 `16 / 14 / 12` 秒，耗魔 `90 / 110 / 130`。 | **封界延时**：眩晕时间增加 `0.2 / 0.4 / 0.6` 秒；修正键 `stun_duration_tenth_add`。 | **雷火贯穿**：本技能伤害 `+20% / +40% / +60%`；修正键 `damage_percent_add`。 |
| E / `A0B3` | 灰袍援护 | 被动 | 甘道夫周围 500 范围内的友方英雄受到伤害后生命降至最大生命的 35% 以下时，甘道夫为该目标恢复 `0.8 / 1.1 × 智力` 生命。每名甘道夫有独立的 22 秒内部冷却。 | **不灭火光**：援护治疗量 `+20% / +40% / +60%`；修正键 `healing_percent_add`。 | **同伴之誓**：援护范围增加 `100 / 200 / 300`；修正键 `area_add`。 |
| R / `A0B4` | 白焰界域 | 指向地面 | 在指定位置创建半径 350 的白焰区域，持续 3 秒、每 0.5 秒造成一次范围伤害；每次伤害为 `0.3 / 0.4 × 智力`，基础共 6 次。冷却建议 `70 / 60` 秒，耗魔 `160 / 200`。 | **不灭之焰**：额外增加 `2 / 4 / 6` 次灼烧脉冲；修正键 `pulse_count_add`。 | **焚界扩张**：作用半径增加 `60 / 120 / 180`；修正键 `area_add`。 |

技能顺序保持明确：Q 用来压低单个目标或弹射清理散怪；W 可打断危险施法；E 在队伍英雄濒危时自动救援；R 用于覆盖怪群和限制区域。R 的肉鸽额外脉冲按 0.5 秒间隔延长区域存在时间，不额外缩短脉冲间隔。

每个肉鸽效果最高三级，玩家可以分别升级同一技能的两个分支。例如，星火连锁与白焰聚焦能够同时生效。弹射伤害按每一跳依次结算，禁止在同一次施法中重复命中同一单位。

## 4. 技能机制实现

### 4.1 Lua 模块边界

建议新增 `Build/map/Lua/rogue/skills/gandalf.lua`，负责甘道夫 QWER 的事件、定时器、救援冷却、临时状态和特效清理；由 `rogue/main.lua` 在肉鸽系统启动时启动该模块。现有 `hero_damage.lua` 中专属 `H0B0` 的裂地伤害和牛魔王反击逻辑应在实施时迁出或替换，避免新旧机制同时触发。

- 技能伤害读取 `config.get_skill_runtime("H0B0", abilityRawcode)`，倍率通过 `combat.skill_damage.calculate` 计算。
- 技能伤害调用 `combat.damage.deal`，不使用物编直接伤害或其他独立扣血接口。
- 技能治疗使用 `combat.recovery.calculate_fixed` 和 `combat.recovery.apply_fixed`；治疗值按甘道夫智力计算，再应用到被援护英雄。
- 肉鸽参数从该玩家的技能效果状态读取，不在模块中按具体效果 ID 写死分支数值。
- 每次施法的坐标、目标、定时器、脉冲序号和特效句柄均保存在施法实例状态中，多个玩家同时施法时不得共用可变的模块级临时数据。

项目当前的伤害事件服务支持订阅受伤报告并注册目标。甘道夫启动时，应把可被援护的玩家英雄注册为伤害事件目标；援护监听只响应友军英雄且需检查甘道夫存活、距离、目标生命比例和内部冷却。若后续发现伤害事件服务未覆盖某类友军单位，应在服务注册流程中补齐目标，不能另建一条绕开项目统计的伤害监听。

### 4.2 Q：星火术

1. 物编使用敌方单位目标技能，配置射程、热键、冷却和耗魔；技能物编直接伤害设为 0。
2. `EVENT_PLAYER_UNIT_SPELL_EFFECT` 捕获施法者和目标单位。Lua 检查目标仍存活且为敌方后，再结算一次基础伤害。
3. 如果具备 `bounce_count_add`，从上一目标周围 350 范围搜索尚未命中的最近敌人；距离相同时按单位句柄 ID 排序，保证所有客户端结果一致。
4. 每次弹射记录已命中单位集合。基础目标加上肉鸽弹射数是本次施法的最大目标数；死亡目标不再结算，并按确定性规则继续寻找合法目标。
5. 单体伤害加成只修改星火术的基础伤害；弹射支数只改变弹射上限，两项可组合生效。

首版建议使用命中即结算的法术效果，不做 Lua 手工追踪飞行弹道，避免 1.27 环境中弹道视觉与实际碰撞结果不一致。若保留原生飞弹，仅作为演出，并在目标客户端检查伤害时机是否能接受。

### 4.3 W：法杖封界

1. 物编使用敌方单位目标的远程控制技能壳，设定技能等级、射程和眩晕时长；壳的直接伤害必须设为 0。
2. 原生技能壳负责施法目标约束、飞弹/命中控制表现和眩晕 Buff；Lua 在技能事件中读取目标与施法等级，按 `damageMultiplierTenth` 结算伤害。
3. `stun_duration_tenth_add` 以十分之一秒为单位修正眩晕持续时间。应使用技能专属 Buff 或可控的物编时长字段；不要直接 `SetUnitPaused` 后再用独立计时器恢复，以免覆盖其他眩晕、击退或暂停状态。
4. 多人施法测试需确认原生眩晕只触发一次，Lua 只负责伤害，不再额外套一层相同控制。

W 的基础目标是单个敌人。首版不添加随机选目标或多目标控制，避免与 Q 的弹射定位重叠。

### 4.4 E：灰袍援护

1. 甘道夫登记自己的友军英雄集合，并为这些目标调用 `combat.damage.register_target`；通过统一伤害服务订阅目标受到的伤害报告。
2. 事件发生后读取目标当前生命和最大生命。只有目标是友军英雄、仍存活、生命比例低于 35%、位于甘道夫援护范围内且该甘道夫冷却已结束，才触发援护。
3. 治疗量使用 `recovery.calculate_fixed(gandalf, healMultiplierTenth, healingPercentAdd)` 计算，并调用 `recovery.apply_fixed(target, amount)`；该技能只在本次跨入濒危阈值时触发，治疗后不会因仍低于阈值连续触发。
4. 每名甘道夫独立维护 22 秒冷却。若两名甘道夫同时覆盖同一目标，建议先按事件顺序触发第一名并共享目标短暂锁定，避免同一受击报告瞬间重复治疗；该规则需在肉鸽/队伍规则评审时确定。
5. 范围肉鸽使用 `area_add` 修正检测半径；治疗肉鸽只提高恢复量，不改变触发阈值和冷却。

这里采用即时恢复而非吸收盾。现有项目已提供统一恢复服务；通用护盾目前没有专门服务，若将来决定改为吸收伤害，应先设计并测试集中式护盾结算，再调整本技能，不在本稿中假设一个尚未存在的护盾 API。

### 4.5 R：白焰界域

1. 物编使用指向地面的施法方式，允许 Lua 读取 `GetSpellTargetX/Y`；设定施法距离、冷却和耗魔，物编周期伤害关闭。
2. Lua 记录每个施法实例的中心坐标、范围、结束时间、脉冲序号和修正后的最大脉冲数。基础脉冲数为 6，额外脉冲只增加持续时间。
3. 每 0.5 秒创建一轮范围检测；每名敌人每轮只受一次伤害。单次脉冲倍率根据技能等级读取配置，肉鸽伤害加成按统一技能伤害服务结算。
4. 一个单位可同时处于不同玩家释放的区域内；不同施法实例分别结算。相同玩家重新施放是否覆盖旧区域，首版建议允许并存，但限制每个英雄最多 2 个活动区域，超过上限时清理最早的一处，控制定时器和特效数量。
5. 脉冲计时器结束、施法者退出游戏或地图清理时，销毁计时器、群组和持有的所有特效句柄。

所有区域半径以 Lua 伤害判定为准，物编只提供施法范围提示。若目标客户端无法稳定显示 FlameStrike 地面效果，可退回到落点的短促火焰爆发，不影响 Lua 脉冲逻辑。

## 5. 多人同步与性能要求

- 伤害、治疗、冷却、目标选择、脉冲计时器和肉鸽层数均为同步游戏状态，所有客户端运行同一逻辑；不得放在 `GetLocalPlayer` 分支内。
- Q 弹射的候选目标排序固定为距离优先，再以单位句柄 ID 作平手裁定；不使用客户端本地随机。
- E 的低血量判断统一使用整数生命值百分比比较，避免浮点分支差异；恢复值使用项目统一的整数公式。
- R 每次枚举后销毁单位组；限制并存区域数量；死亡或离场目标不继续触发伤害。
- 临时特效有固定生命周期，脉冲命中特效不能无限堆叠；每个施法结束或清理阶段都要释放关联特效和计时器。
- 按项目 1.27 兼容要求，不依赖 `BlzSetSpecialEffectPosition` 等高版本接口。移动弹道如确有必要，应使用经过验证的原生技能弹道或 Lua 驱动的临时单位。

## 6. 原生魔兽特效方案

首版优先使用 Warcraft III 原生模型。模型只负责视觉表现，碰撞、范围、伤害和治疗由 Lua/原生 Buff 机制负责。以下路径是候选值，导入或生成地图后仍须在目标 1.27 客户端逐项检查存在性、挂点、朝向和显示时机。

| 用途 | 原生模型路径 | 建议用途 |
|---|---|---|
| Q 星火命中 | `Abilities\\Spells\\Human\\HolyBolt\\HolyBoltSpecialArt.mdl` | 在目标身上短暂播放圣光爆发；每次弹射只在实际命中单位处创建一次。 |
| Q 额外弹道备选 | `Abilities\\Weapons\\PhoenixMissile\\Phoenix_Missile_mini.mdl` | 如果设计评审决定要显式飞行弹道，可用作火焰飞弹候选；必须检查弹道外观是否适合甘道夫。 |
| W 控制命中特效 | `Abilities\\Spells\\Human\\Thunderclap\\ThunderclapCaster.mdl` | 在目标位置播放短促冲击光效；眩晕图标/持续时间仍由技能 Buff 表现。 |
| E 援护治疗 | `Abilities\\Spells\\Human\\HolyBolt\\HolyBoltSpecialArt.mdl` | 在被治疗英雄身上播放一次浅色恢复闪光；不叠加持续光环特效。 |
| R 区域预警 | `Abilities\\Spells\\Human\\FlameStrike\\FlameStrikeTarget.mdl` | 施法后短暂标记地面落点，让玩家看清区域中心。 |
| R 白焰脉冲 | `Abilities\\Spells\\Human\\FlameStrike\\FlameStrike1.mdl` | 每次脉冲创建一次短时火焰爆发；不依赖该特效本身造成伤害。 |
| R 地面余烬 | `Abilities\\Spells\\Human\\FlameStrike\\FlameStrikeEmbers.mdl` | 可选的区域持续视觉；必须限制存在时长和并存数量。 |

HolyBolt 的命中特效与 InnerFire 的目标效果路径可参考 [Warcraft III World Editor 原生路径列表](https://www.realprogramm.narod.ru/Warcraft3WorldEditor.htm)；Thunderclap 效果示例可参考 [JudgeHype 特效教程](https://warcraft3.judgehype.com/editeur4/)；FlameStrikeTarget 路径可参考 [WC3Edit 路径讨论](https://forum.wc3edit.net/viewtopic.php?t=8327)。这些资料只用于定位候选资源，最终仍以项目目标 1.27 客户端实测为准。

### 6.1 弹道与命中表现

1.27 下 `AddSpecialEffect` 负责在坐标生成特效，不作为通用可移动弹道接口。首版优先使用命中时的目标附着/坐标特效；若视觉评审要求飞弹，再使用原生目标技能的飞行弹道，或者 Lua 驱动的视觉弹道单位。

不允许用同一发技能同时触发原生伤害和 Lua 伤害。Q、W、R 的物编直接伤害、周期伤害都设为 0；W 如保留原生眩晕，只让物编负责控制，伤害仍由 Lua 结算。

## 8. 物编技能壳要求

- Q 使用敌方单位目标技能壳，建议采用火焰/圣光风格的原生目标技能；原生直接伤害关闭，命中光效可保留。
- W 使用敌方单位目标控制技能壳；原生眩晕可保留，原生伤害必须关闭。肉鸽延长眩晕时长应与物编 Buff 时长采用同一修正来源，避免双重施加。
- E 为被动技能，不产生物编治疗；Lua 检测触发条件并经 `combat.recovery` 恢复生命。
- R 使用指向地面的目标方式，Lua 负责脉冲范围、次数和伤害；物编的周期伤害关闭。
- 使用原生技能模板前，核对订单字符串、目标类型、目标允许项和实际 Buff。不能只更换名称后沿用不匹配的父级。
- 技能壳范围、射程、冷却和耗魔应与运行时配置及选将面板同步。

## 9. 验收测试

### 单人机制

- Q 只对施法目标造成一次基础伤害；弹射仅命中范围内、未被本次 Q 命中过的敌方单位，三级目标数正确。
- Q 的伤害分支与弹射分支可分别升级，叠加后伤害与跳数符合配置，没有重复命中。
- W 目标合法、射程正确，眩晕和 Lua 伤害均只结算一次；加长眩晕分支按 0.2 秒刻度生效。
- E 仅对范围内的友方英雄生效；目标低于 35% 生命时触发一次，内部冷却内不会反复治疗；治疗量随甘道夫智力和肉鸽加成变化。
- E 的范围分支不会扩大到敌方单位；多个甘道夫覆盖同一目标时行为符合约定。
- R 基础持续 3 秒并产生 6 次脉冲；额外脉冲分支延长持续时间，范围分支只修改半径；同一脉冲对每个目标最多造成一次伤害。
- 技能等级、冷却、耗魔和面板说明与实际效果一致；初始主属性修改后，伤害和治疗均读取智力。

### 肉鸽与配置

- `H0B0` 四个技能各恰有两个专属肉鸽效果，每个效果最高三级。
- 效果只修改甘道夫对应技能；Q 的弹射、W 的眩晕时长、E 的治疗/范围、R 的脉冲/范围不会影响其他英雄。
- 配置生成器校验 Rawcode、效果数量、三级整数数组和技能运行时参数；生成后的文件不做手工修改。
- 选将界面、技能图标、技能描述和奖励卡牌不再显示牛魔王技能或旧的嘲讽/反击数值。

### 多人同步与构建

- 两名甘道夫同时施放 Q/W/R 时，弹射顺序、目标、伤害、眩晕、脉冲位置和结束时间在所有客户端一致。
- 多名友方英雄同时受伤时，E 仅在合法目标进入阈值且救援冷却结束后触发；多人视角显示一致。
- 英雄死亡、目标离场、区域结束或游戏清理时，所有计时器、群组和特效对象均被释放。
- 完成 Excel 配置生成、Lua 语法检查、地图构建，再使用目标 1.27 客户端验证原生技能壳、Buff 和特效路径。
