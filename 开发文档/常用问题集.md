# 九斗项目常用问题集

本文记录技能、特效、模型资源和 xlik 构建中反复出现的问题。每次修改英雄技能、肉鸽分支、模型或贴图时，先按“快速排查顺序”检查，再进行游戏画面验证。

## 快速排查顺序

1. 确认源文件：Excel、Lua、MDX/BLP 是否改在正式源目录。
2. 确认生成：运行 `generate_lua_config.bat`，检查生成的 abilities、roguelike、units 和 SLK。
3. 确认技能壳：检查 `_parent`、`DataF`、`Order`、目标类型、魔法消耗、冷却和按钮位置。
4. 确认脚本路径：运行时特效模型路径必须和 `assets/model.lua` 的声明一致。
5. 确认资源包：解包最终 `pack.w3x`，检查 MDX 和所有自定义 BLP 是否存在。
6. 最后才做游戏内验证。静态构建通过不能代替游戏内验证。

## 1. 多个技能释放出来的特效都一样

### 常见原因

- 技能继承了错误的原生父级。
- `DataF` 或 `Order` 仍然使用原生技能命令，例如 `berserk`、`deathcoil`、`carrionswarm`。
- 运行时脚本创建特效后立即 `DestroyEffect`，不同模型只显示同一帧的默认表现。
- 脚本实际使用的是同一个模型路径，或者模型别名和直接路径混用。

### 检查方法

在源表 `excelCfg/ability.xlsx` 检查目标 Rawcode，再检查生成配置：

```powershell
rg -n -C 8 '\["A0E2"\]|DataF|Order|_parent' Build/projects/JiuDou/scripts/globals/config/abilities.lua
```

点目标、由 Lua 完整结算的技能通常使用 `ANcl` + `channel` 壳：

```lua
["_parent"] = "ANcl"
["DataF"] = { "channel", "channel", "channel" }
["Order"] = "channel"
```

不要为了让 Lua 接管伤害，继续保留 `berserk` 等会产生原生视觉的命令。

### 运行时要求

- 一次性命中特效要保留一小段时间后再销毁。
- 持续模型要单独保存句柄，在持续时间结束时销毁。
- 每一种技能的模型常量必须不同，并在创建处直接传入对应常量。
- 清理逻辑必须在技能结束、模块停止和生命周期卸载时执行。

## 2. MDX 存在，但游戏中显示白模、紫色默认效果或完全看不到

### 资源路径规则

模型文件放在：

```text
Build/vendor/assets/war3mapModel/
```

正式模型声明放在：

```lua
-- Build/projects/JiuDou/assets/model.lua
assets_model("effect/ArthasIceTornado", "arthas_ice_tornado")
assets_model("effect/ArthasFrostBolt", "arthas_frost_bolt")
```

本项目运行时使用别名生成的路径：

```text
war3mapModel\arthas_ice_tornado.mdx
war3mapModel\arthas_frost_bolt.mdx
```

如果 MDX 内的自定义贴图仍引用 `war3mapImported\foo.blp`，不能只移动 BLP 文件；必须先在 `New` 副本中把完整 TEXS 路径改为 `war3mapTextures\foo.blp`，再进行模型测试：

```text
MDX: war3mapTextures\foo.blp
BLP: Build/vendor/assets/war3mapTextures/foo.blp
测试阶段：Build/vendor/assets/war3mapTexturesNew/foo.blp
```

由工程测试和打包流程负责解析、引入和验证贴图。`Build/projects/JiuDou/w3x/resource/` 禁止作为资源源目录，不能通过手工复制文件来修复模型贴图问题。

不要只把贴图放在 `.codex_tmp`、`Build/.tmp` 或模型预览目录；这些目录不会自动进入最终地图。

### 必查项目

- MDX 中的贴图文件名与正式资源文件名完全对应，大小写也保持一致。
- 复用的贴图先比较 SHA-256，不要复制多个不同版本的同名文件。
- 模型预览通过只说明预览工程成功，必须继续检查最终 `pack.w3x`。
- 最终地图包解包后，MDX 与 BLP 必须同时存在。

## 3. xlik 日志显示“模型 Textures 引入：0张”

如果日志显示“模型 Textures 引入：0张”，优先检查 MDX 是否仍使用 `war3mapImported\...` 路径。正式工程要求改为 `war3mapTextures\...`；只有日志显示贴图已引入并且最终包解包能找到 BLP 时，才能认定依赖进入地图。

以最终包为准：

```powershell
& '.\Build\vendor\w3x2lni\w2l.exe' unpack `
  (Resolve-Path '.\Build\.tmp\_test\JiuDou\pack.w3x').Path `
  (Resolve-Path '.\.codex_tmp').Path+'\verify-pack'
```

检查解包目录中的：

```text
verify-pack/war3mapModel/
verify-pack/war3mapImported/
```

## 4. 特效创建后只闪一下，或者所有特效看起来相同

错误写法：

```lua
local e = jass.AddSpecialEffect(path, x, y)
jass.DestroyEffect(e)
```

正确做法是让技能模块持有句柄，并延迟销毁：

```lua
local e = jass.AddSpecialEffect(path, x, y)
timer_service.after(0.9, function()
    if e ~= nil then jass.DestroyEffect(e) end
end, runtime_scope)
```

持续特效不能用一次性特效的清理方式。应记录 `active_tornadoes`、`active_frost_bolts` 等状态，在到期或模块停止时统一清理。

## 5. 学习了技能，但技能栏没有图标

检查以下项目：

- Excel 行中的 `hero=1`、按钮位置和学习按钮位置是否正确。
- 技能是否真的加入英雄的技能列表，而只是创建了一个展示用或隐藏技能。
- Rawcode 是否重复，脚本使用的 Rawcode 是否与 Excel 相同。
- 生成后的 `abilities.lua`、`generated_ability.lua` 是否包含该技能。
- 技能图标路径是否存在于 `Build/vendor/assets/war3mapImage`。

不要直接修改生成的配置来补图标；先修正 Excel 或英雄技能注册，再重新生成。

## 6. 技能没有耗蓝，或者冷却显示方式和其他主动技能不同

魔法消耗和冷却必须以 Excel 技能行作为源数据：

- `Cost` 为零表示技能不耗蓝。
- `Cool` 负责技能栏的原生冷却显示。
- Lua 中的自定义计时器只用于额外机制，不能再单独伪造普通技能冷却提示。

修改 Excel 后必须重新运行生成器，不能只改 `abilities.lua`。

## 7. 自身施放没有回复生命

确认技能逻辑走统一恢复服务，而不是只播放治疗特效：

```lua
local amount = recovery.calculate_fixed(hero, base_heal, recovery_bonus)
recovery.apply_fixed(hero, amount)
```

同时检查：

- `amount` 是否大于零。
- 目标是否确实是英雄自身。
- 最大生命值和当前生命值是否已更新。
- 治疗特效只是表现，不能代替实际恢复。

## 8. 召唤物没有攻击力或不能攻击敌人

召唤技能要同时检查单位配置和 Lua：

- 单位的攻击字段、攻击范围、攻击类型和基础伤害不能是零。
- 召唤单位的所有者必须正确设置。
- 不能误加 `Aloc`、`Locust` 或其他禁止攻击/选择的能力。
- Lua 计算的伤害目标必须通过 `IsUnitEnemy`，不能把召唤物当成英雄本体。
- 生成后的单位必须有正确的玩家归属和可攻击状态。

## 9. 突然出现命令光环、耐久光环或其他未设计技能

通常是英雄物编或辅助单位继承了错误技能，或把隐藏技能直接添加到了英雄身上。

排查顺序：

1. 查看英雄和辅助单位的技能列表。
2. 检查 `units.xlsx` 的技能字段和生成后的 `units.lua`。
3. 检查隐藏施法单位是否使用了错误的单位 Rawcode。
4. 检查同一个 Rawcode 是否被多个系统复用。

展示用技能、隐藏施法壳和真正的英雄技能应使用不同 Rawcode。

## 10. 亡灵大军或其他召唤技能有时不生效

检查：

- 冷却状态是否在失败时也被写入。
- 召唤数量是否受单位上限或旧召唤物清理影响。
- 目标点是否超出地图边界或不可创建单位。
- 召唤单位创建失败时，是否仍把本次施法标记为成功。
- 技能等级、肉鸽加成和运行时配置的 key 是否一致。

召唤失败时应保留可诊断的计数或日志，不能只播放一个成功特效。

## 11. 肉鸽效果学习了，但运行时没有生效

肉鸽效果至少要同时存在于：

1. `excelCfg/roguelike.xlsx` 的效果定义。
2. `skill_runtime` 或对应运行时配置。
3. 英雄技能脚本读取的 modifier key。
4. 英雄 Rawcode 和效果 Rawcode 的映射。

重点检查名称和 key 的大小写、下划线、Rawcode，以及等级 1/2/3 的数组长度。每个英雄技能应保持设计要求的两条专属分支，不能只改卡片文字。

## 12. 生成文件、临时文件和正式文件怎么区分

### 正式源文件

- `excelCfg/*.xlsx`
- `Build/projects/JiuDou/scripts/...`
- `Build/projects/JiuDou/assets/*.lua`
- `Build/vendor/assets/war3mapModel*`
- `Build/vendor/assets/war3mapTextures*`
- `Build/projects/JiuDou/w3x/resource/` 不是资源源目录，禁止手工放入任何资源。

### 生成文件

`Build/projects/JiuDou/scripts/globals/config/` 和 `Build/projects/JiuDou/slk/` 是由生成器产生、供地图构建读取的文件。不要手改生成文件来代替源文件修改。

### 临时和验证输出

- `Build/.tmp/`：xlik 模型预览、测试地图和打包中间目录。
- `.codex_tmp/`：备份、哈希、解包核对和审计文件。
- `outputs/`：项目已有的导出结果目录。

这些目录用于验证，不是新的业务源文件；除非明确要交付地图包，否则不应把临时目录中的文件复制回业务代码目录。

## 每次提交前的最小验收清单

- [ ] 源 Excel/Lua/资源文件已修改，生成文件已重新生成。
- [ ] 技能壳的 `_parent`、`DataF`、`Order` 与设计一致，没有残留原生视觉命令。
- [ ] 每个主动技能的 `Cost`、`Cool`、射程、目标类型和按钮位置已核对。
- [ ] 每个模型的 MDX 引用贴图都能在正式资源目录找到。
- [ ] 一次性特效没有立即销毁，持续特效在结束和模块卸载时清理。
- [ ] `assets/model.lua` 别名与运行时模型路径一致。
- [ ] 运行 `generate_lua_config.bat` 成功。
- [ ] 从 `Build` 目录运行 `tools\xlik.exe run JiuDou -t!` 成功。
- [ ] 解包最终 `Build/.tmp/_test/JiuDou/pack.w3x`，确认模型、贴图、技能配置都在包内。
- [ ] 如果 World Editor 或游戏路径不存在，明确记录为“静态构建通过，运行时未验证”，不要把静态结果写成游戏内通过。

## 本次 W 冰龙卷问题记录

症状：释放 W 时出现紫色旋涡，冰龙卷模型表现异常。

根因：A0E2 仍使用 `berserk` 的 `DataF/Order`，同时 MDX 的自定义贴图路径没有按工程规则转换为 `war3mapTextures`，导致依赖没有进入最终地图资源。

修复：A0E2 改用 `channel`，运行时使用稳定模型别名，将 15 张新增 BLP 放入 `Build/vendor/assets/war3mapTextures/`，并通过工程模型测试和最终解包确认冰龙卷、冰箭模型和贴图均存在。
